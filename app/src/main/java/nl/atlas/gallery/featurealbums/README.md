# ATLAS Albums — exact-folder navigation and photo-first cards

`AlbumCatalog.kt` builds full, deterministic, cancellation-aware summaries in one input pass. `AtlasAlbumsScreen.kt` renders a photographic adaptive cover grid; actual media rendering is delegated to the integrator's permission-aware `MediaPreview` instead of instantiating its own URI-keyed Coil loader. It performs **no media mutations**.

## Integration API for Lane I

`buildAlbumSummaries(media: List<MediaRecord>, sort: AlbumSort, preferredCoverByPath: Map<String,String> = emptyMap(), checkActive: (() -> Unit)? = null, mediaFilter: AlbumMediaFilter = ALL, volumeOf: (MediaRecord)->String = {"external"}, preferredCoverByBucket: Map<AlbumBucketKey,String> = emptyMap()): List<AlbumSummary>`

- Run on `Dispatchers.Default`, cancel on MediaStore generation change, and expose only a complete snapshot whose original source generation is still current. Do not rebuild in composition or publish a stale partial snapshot.
- Identity is `AlbumBucketKey(volumeName, exact RELATIVE_PATH)`. Two folders named `Camera` on different directories **or mounted volumes** are distinct. When **visible album titles collide** (including accent/case-insensitive similarities), `AlbumSummary.locationLabel` now supplies a source-backed caption: parent folder when sufficient (`DCIM` versus `Pictures`), a storage label for the same folder on two volumes, or exact relative path plus storage for otherwise ambiguous siblings. **Unique-title albums have no extra chrome.** The caption is non-authoritative: all navigation, covers and previews still use exact bucket and current grant. A blank root is distinguishable from a literal top-level folder named "On device". To use Lane M's newly authored `MediaRecord.volumeName`, I must pass `volumeOf = { it.volumeName }` after M integration (the compatible default is only a single-volume fallback). Never infer album identity from a display name, path substring, filename or bare numeric media ID.
- Each `AlbumSummary` carries `coverMedia: MediaRecord?`, pointing to the **actual current authorized catalogue object** (not just `coverUri`), so the cover renderer can apply the full M revision and I publication-epoch policy. A missing source item means a neutral placeholder, never a historical URI decode. Cover defaults to the newest accessible **photo** (or newest video for a video-only folder). An optional manual URI is admitted only if present in the identical current source bucket; `preferredCoverByBucket` supports per-volume choices, while `preferredCoverByPath` is only a legacy single-volume fallback. Persisting preferences is future I/X work. No originals are copied, no independent thumbnail cache.
- Use `AlbumProjectionSnapshot(source,sort,mediaFilter,coverRevision,albums,accessEpoch)` and `currentAlbumProjectionOrNull(...,accessEpoch)`: results are accepted only for the **same inventory object** (not an equal-valued stale generation), sort, filter, cover revision **and permission/publication epoch**. Changing or losing permissions requires rebuilding with the freshly authorized inventory. I/M must invalidate revoked Coil images; this projection does not grant access.
- `AlbumSort.RECENT/NAME/COUNT` sorts albums, **not** photo ordering inside an album. Preserve existing NEWEST/OLDEST/LARGEST/RANDOM media sorting and exact album selection. Name order is accent/case-insensitive, natural for numbers, and deterministic on exact-path tie. **Name normalization is precomputed once per album**, rather than in each O(albums log albums) comparator call; do not regress that during integration.
- Media counts include video; count badges and accessibility metadata are source-backed. No artificially inferred People, locations or categories.
- `AlbumMediaFilter.ALL/PHOTOS/VIDEOS` filters the actual MediaRecord items **before grouping and counting**. The selected filter must be included in the background projection key and recomputed on generation changes. No filename-based media type guesses.
- `AtlasAlbumsScreen(albums, sort, onSort, onOpenAlbum, mediaFilter, onMediaFilterChange, isLoading, onOpenLibraryStatus, coverRenderer)` is controlled: I must supply newly grouped/sorted albums after **either** filter or sort changes. `onOpenAlbum` receives `AlbumRoute(relativePath, mediaFilter, volumeName)`; I must enforce **all three** for the in-album grid/filmstrip and restore them on Back. Passing only the folder path will misrepresent the filtered count and cover.
- **Empty** `RELATIVE_PATH` is valid; never treat it as an 'all photos' sentinel or suppress its route. `AlbumRoute("", ALL, volume)` remains a real root album. Separate nullable selected-album state from this exact-path key.
- Screen state retains filter/sort ownership at I. No hidden indexing button, no automatic scanner, no direct MediaStore action.
- **Cancellation now covers all O(folders) and O(folders log folders) phases:** scan every 512 records, snapshot-name normalization every 512 albums, all sort modes every 1,024 **outer** comparisons (including unique Recent times and Count totals), and before/after final result publication. I must pass a live coroutine `job.ensureActive()` callback rather than a no-op to reject obsolete scope when many distinct albums exist.
- `AlbumLoadIssue.ACCESS_NOT_GRANTED` / `READ_FAILED` are **safe display categories**. Optional `loadIssue` suppresses stale album cards; ACCESS_NOT_GRANTED offers a Library status action **only if** `onOpenLibraryStatus` is supplied, while READ_FAILED offers Retry only if `onRetry` is supplied. Avoid passing raw exceptions, absolute media paths or provider debug messages. `isLoading` takes precedence over an old error during retries.
- `isLoading=true` hides the **entire former card grid** until an authorized projection is ready, regardless of whether a stale `albums` list still exists; I should set this while the source is superseded and must not pass stale albums as ready. Filtered empty states now have a working **Show all albums** action. Empty-state content scrolls at large fonts/landscape, and cards identify themselves as buttons to TalkBack without duplicate "Open" text. The stock Material FilterChip already announces selected state.

### 24 October same-URI/source-revision consistency

Both reverse and forward source publications choose the same `coverMedia` record for same-URI/same-date source conflicts. ## 24 October: grant-bound session-only cover preferences

New `AlbumCoverPreferences.kt` and seven synthetic JUnit methods in `AlbumCoverPreferencesTest.kt` make the missing I-owned preference plumbing simple without introducing a database, MediaStore mutations, URI retention across grant changes, new permissions, or a second index of 150k photos.

- **Construct only from published current authority:** `var coverPrefs = AlbumCoverPreferences.start(liveAuthorizedSource, publishedEpoch)` during an actual opt-in cover-picker session. The session is an immutable value class with `source` **reference identity**, `accessEpoch`, monotonic `revision`, and at most **4,096** exact `AlbumBucketKey(volumeName,relativePath) -> current URI` choices. The cap prevents unbounded session preferences for tens of thousands of virtual folders.
- **On user selection:** after I has independently confirmed its *currently live* Android MediaStore grant, call `coverPrefs.chooseOrNull(pickerProjection, typedAlbumCoverChoice, liveSource, liveEpoch, exactRoute, currentPermissionScope=verifiedPermissionScope)` if an independent stable token is in use (otherwise omit it only for the conservative default). It refuses mismatched source reference, epoch, exact album route, candidate URI, source-record instance and forged bucket. A successful call returns a **new** preference session with `revision+1`; repeated identical selection is an O(1) no-op. An old composable callback from a prior grant/source cannot change the new session.
- **On background Album projection:** for a separately verified stable permission token, first fetch `val currentPrefs = coverPrefs.currentOrNull(liveSource,liveEpoch,currentPermissionScope=verifiedPermissionScope)` and pass `preferredCoverByBucket = currentPrefs?.preferredCoverByBucket ?: emptyMap()` and `coverRevision = currentPrefs?.revision ?: 0L` to the corresponding projection key and snapshot; for the conservative default only, omit the explicit scope argument. `currentOrNull`, `chooseOrNull` and `clearOrNull` **all** require the exact *currently verified permission-generation token on every read/write**, not just once per rebase. An old token must hide historical covers immediately even if the source and publication epoch have not yet changed. use the **same** captured preference revision and source reference in the projection's publish-admission check. The existing `buildAlbumSummaries` still verifies that each chosen URI is in the exact authorized album bucket; it falls back to an available photo if not. No original changes.
- **Publication epoch is not a permission epoch.** Live I's `GalleryPublishedInventory.epoch` identifies an authorization-validated **catalogue publication**, so it can advance after an ordinary refresh with *unchanged permission grants*. The safe default `AlbumCoverPreferences.start(source,publicationEpoch)` / `rebase(newSource,newEpoch)` treats every new publication epoch as an unknown new grant and **purges preferences**; this is privacy-safe but loses custom covers too often if used as the sole integration mode. Do **not** falsely describe publication-epoch changes as proof the Android photo grant changed.
- **Optional independently verified stable grant token:** I can maintain `AlbumCoverPermissionScope(permissionGeneration)` as its **own monotonic permission-lifecycle token**, changing on **every revoke, regrant, scope change, Activity scope mismatch or unverified grant transition**, but keeping it unchanged across successful MediaStore inventory refreshes under the *same continuously confirmed grant*. If that exact verified grant token is unchanged, the controller rescans the **new authorized catalogue** and retains **only** exact present folder+volume+URI matches; on a token change **all** historical preferences clear, even if publication epoch/source/URI remain unchanged. It refuses to carry choices to an older out-of-order publication epoch, regardless of token. A stable token **must never be synthesized from a URI, inferred from album names, or equated to publication epoch**. Until I actually implements a verified permission-generation source, use the conservative default. A sole comparison of `GalleryMediaGrant` bits without a revoke/regrant generation is **insufficient** to prove uninterrupted permission scope.
- **Performance:** O(media count) rebase only when custom covers exist; empty-preference case rebinds in O(1) after one cancellation checkpoint, even for 150k source rows. No structural `List.equals`, no source-list copy, no old photos held after a grant-generation change. I must not let an out-of-order old worker publish its rebase after a newer scope and must validate source+publication epoch again on the main-state admission barrier.
- **On clear/reset:** `clearOrNull(exactBucket,liveSource,livePublicationEpoch)` drops one session-only override and increments revision without destructive action.
- **CPU budget and failure semantics:** one off-main O(media count) scan only when at least one selection is present; bounded preference memory; every 512 MediaRecords checks cancellation; exceptions propagate rather than publishing partially validated preferences. User-visible failure/retry must remain within I's current grant and never continue with stale retained covers.

### Permission-generation-aware picker paging (24 October)

All cover **projections, exclusive older-page cursors, navigation sessions and
the Compose chooser** now accept an optional `AlbumCoverPermissionScope`.
The backward-compatible default follows the catalogue publication epoch and
conservatively rejects custom-scope pages. To accept a long-running chooser
within a single genuine Android grant, I must pass an **independently verified**
scope token to `start`, `buildAlbumCoverChoices`,
`currentAlbumCoverChoicesOrNull`, `olderOrNull`, `newerOrNull`,
`chooseAlbumCoverOrNull`, `AtlasAlbumCoverChooser` and
`AlbumCoverPreferences.chooseOrNull`. Never infer the token from
`publishedGallery.epoch` alone; mint a new one on Android revoke,
regrant or partial-grant changes. Revalidate live Android permissions before
all mutations. A changed scope rejects even the same source list and epoch.

Integrate `AlbumCoverChoice.kt`, `AlbumCoverPageSession.kt`,
`AlbumCoverPreferences.kt`, `AtlasAlbumCoverChooser.kt` and the
three corresponding tests atomically. This does not save URIs, write
MediaStore, change Android permissions or touch MainActivity.
