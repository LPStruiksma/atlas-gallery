# ATLAS design lane — clean-room gallery-first components

Source basis: `docs/ATLAS_NEXT_GENERATION_PARALLEL_ROADMAP.md` and Samsung parity research Appendix B/D, independently interpreted. This is original Compose, not Samsung code/assets.

## Intent and user flow

- The primary navigation is **Photos / Albums / People / Search**. Technical refresh, import provenance, indexing status and diagnostics move to **Library activity and settings** through the header's ⋮ overflow menu; never hide permission warnings or replace them with decorative animations.
- Let original photos dominate. Gallery chrome uses restrained near-neutral surfaces, understated tidal-green controls, legible titles, generous 48 dp targets and compact, meaningful secondary copy.
- Dark and light schemes are supported through `AtlasGalleryTheme`, but the integrator chooses the system bar colours and applies the theme at root. No global app files are modified in this lane.
- Never fake a face-discovery entry point. Until Lane P/U actually delivers it, People continues to state that native face discovery is unavailable and V4 is an optional route to confirmed names.
- Keep ATLAS value distinctive: exact local folders, **Largest** and deterministic **Random**, B&W-folder filter, reviewed People, and eventually explainable keeper decisions. No hidden photo upload, deletion, vendor metadata writes or indexer illusions.

15. Latest D `AlbumCoverPreferences` distinguishes **catalogue-publication epoch** from an optional independently verified, monotonically minted `AlbumCoverPermissionScope`. Because I's `GalleryPublishedInventory.epoch` advances on publication, preserving a choice across an ordinary refresh needs a *separate* permission-generation token that stays stable only through uninterrupted verified grant scope. D's default (token derived from publication epoch) deliberately clears preferences whenever the publication advances. Exact live token is required on **every** `currentOrNull`, `chooseOrNull` and `clearOrNull` call, so a revoke/regrant cannot expose an old cover even before publication changes; changed scope or rolled-back publication clears. New 8th committed JUnit regression covers cross-publication continuity vs changed-grant and rollback. Source-aligned Kotlin host **22/22 scenarios PASS** (not exact-blob JUnit, Compose, Gradle or S24+); actual verified permission-generation minting and async publication remain I-owned.
