## Deliver in one bounded patch (at most 12 changed regular text files)

1. `app/src/main/java/nl/atlas/gallery/featurestories/events/`: a **pure Kotlin**, Android-free deterministic segmenter. Accept immutable caller-provided metadata: stable synthetic-safe media key, capture time, optional coordinates with accuracy, optional *confirmed* person IDs, optional visual-similarity signal already computed by the caller, and source/screenshot/download/hidden/trash flags. Return explainable **suggested** event/trip candidate projections with evidence and uncertainty. Make thresholds named and documented. Avoid presenting a guessed event name or place as a fact. No persistence, MediaStore queries, new model, imports from Android, or second media index.
2. Separate event/day-gathering from multi-day trip candidates using conservative, deterministic time gaps plus location or verified participant/visual evidence. A daily commute, screenshots and downloads, home↔work repetition, GPS noise, unrelated adjacent photos, untrusted/missing date/location, and hidden/trashed media must not create confident trips. A segment must not cross long temporal gaps by similarity alone. Missing evidence means no confident inference; stable ordering and duplicate-key/visibility semantics must be explicit. Home inference, if implemented, is on-device from sufficiently repeated nighttime metadata, optional/uncertain, and never exposes a precise home coordinate in outputs or logs.
3. `app/src/test/java/nl/atlas/gallery/featurestories/events/`: JUnit JVM tests for positive synthetic weekend trips and gatherings; hard-negative commute, screenshots/downloads, unrelated images, GPS jitter, temporal gaps, missing/invalid time and coordinates, duplicate/hidden/trashed veto, deterministic shuffled input, no invented place label. Include a **seeded synthetic generator** and 150,000-item cost measurement, with documented command, elapsed time, memory/projection size or allocation proxy where feasible, and environment. Do not assert a measured latency until actually run; avoid flaky timing-based test failures on CI.
4. `docs/product/EVENTS_0.md`: rules and threshold rationale, home-location inference kept entirely on device, evidence-vs-hypothesis boundary, hard negatives, seeded generator coverage, reproducible 150k benchmark and its actual observed result **only if measured**, and **aggregate-only** optional owner check (counts and timing only; no raw GPS, home/work positions, timestamps, People IDs, URIs, embeddings, filenames or media uploaded). Document false-positive/false-negative tradeoffs and unmet risks honestly.
5. Update `docs/product/ATLAS_VISION.md` Stories row and M5 to reflect this *feasibility* segmenter only, not production-shipped trips. List follow-up units **EVENTS-1** store, **EVENTS-2** UI requiring Design brief/preflight under BRAND-0 #628 / Lapis #654, and optional highlight reel using QUALITY-0 signals. PLACES-0 #579 may be used later when genuinely available, not assumed present.
