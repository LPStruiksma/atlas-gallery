## Probe sequence

Two independently installed debug-only fixture APKs with distinct UIDs and no shared UID/process overrides. The recipient starts the narrowly signature-gated publisher Activity for result. The publisher verifies the exact caller package/signature, commits fixed synthetic payload and persistent grant count, sends one read-only ClipData grant and finishes normally. The recipient's original Activity owns the grant and reads MIME first, metadata and digest via ContentResolver. Later fixed nonce-bound broadcasts target the application-context receiver without Activity launch or a new grant. The publisher status-only action after reconstruction cannot grant. No URI/token or raw dump is stored in evidence.

The host uses `run-as` exclusively for atomic fixture JSON records (never provider bytes), verifies UID via `pm list packages -U`, PID/name and uniqueness via `ps -A -o USER,PID,NAME`, and compares task/instance and live ActivityRecord. URI permissions must show a single exact owned read-only entry with one original ActivityRecord; equality is retained in ephemeral host memory. The API29/33/35 AOSP source formats are hypotheses until the actual image run: provider blocks/Connections arrows from ContentProviderRecord, numeric `oom: max=... set=...` (API29) or `oom adj: ... set=...` (API33/35) from ProcessRecord/ProcessStateRecord, and UriPermission's mode/owned/global/persistable/persisted plus readOwners. See the [API29 source](https://github.com/aosp-mirror/platform_frameworks_base/tree/android-10.0.0_r47/services/core/java/com/android/server), [API33 source](https://github.com/aosp-mirror/platform_frameworks_base/tree/android-13.0.0_r1/services/core/java/com/android/server) and [API35 source](https://github.com/aosp-mirror/platform_frameworks_base/tree/android-15.0.0_r1/services/core/java/com/android/server). Unsupported/ambiguous output fails closed.

After positive reread closes its resources, poll both provider connection and publisher set OOM adjustment (SERVICE_ADJ >=500), every 250ms with 20s monotonic deadline. Require both witnesses in one observation, then immediately recheck grant, readiness and exact process identities. Issue one `am kill` of the fixed publisher only. Observe old PID gone within 15s, same recipient PID/task/instance, new publisher PID, same exact read-only grant and digest, unchanged persisted grant count. No retry of a kill, no force-stop, no shell byte read, no regrant. Missing/ambiguous observations and ineffective kill: provider-phase-runner-unsupported; valid readiness timeout: publisher-not-background; grant continuity or digest failure: provider-phase-grant-lost. A changed recipient PID after kill: recipient-died-with-provider. Cleanup uninstalls only fixture packages installed by this run on the sole verified emulator.

## Records and limits

Publisher schema v1: schemaVersion, caseNonce, invocationId, phase, api, publisherUid, publisherPid, verifiedCallerPackage, outcome, grantIssuedCount. Recipient schema v2: schemaVersion, caseNonce, invocationId, phase, api, uid, pid, taskId, activityInstanceId, mime, length, sha256, exceptionClass, released, ownerFinished. Each record is atomically moved to a private per-invocation file. Host uses a unique nonce and invocation, rejects stale, missing, extra and malformed results; status joins on nonce/invocation/phase/API. Probe phase names: grant, reread, post-kill, status. All positive records have ownerFinished:false. Terminal phases: holder, finish-owner, deny, finish-holder. Terminal records retain the original task and instance identity; ownerFinished is true only after the normal owner finish. The URI-free non-exported holder is started within the original task; host requires its exact resumed ActivityRecord and TOP UID state, the unchanged single original read grant, then the original ActivityRecord and recipient grant block absent before and after a real openInputStream denial in the same process. Holder identity is hashed before evidence publication. The 15s bounded poll uses the same 250ms observation interval; missing or ambiguous observations fail closed. No grant is issued by the holder. Remaining separate delivery, broader negative controls and product runner are not implemented.

Normal debug APK is built with the existing mirror and its actual merged manifest checked independently. Any registered production authority fails provider-phases-missing in stage 1; unreadable/unresolved/inconsistent manifest fails provider-detection-invalid. No normal debug/release product-side control code. The eventual CI-only non-distributable shareProof variant must be separately scoped and gap-reviewed; its actual production provider/store must be identical and ordinary artifact isolation machine-proven. Never treat a probe-only or fixture-only receipt as actual provider acceptance. Stage 2 must implement the full issue contract and exact-head matrix before independent other-family review; #1124 and #1123 remain held. No device or performance proof claimed.
