# PERF-25 — Thumbnail binding result admission (synthetic policy proof)

Issue: https://github.com/LPStruiksma/atlas-gallery/issues/309 · parent: https://github.com/LPStruiksma/atlas-gallery/issues/119

## Scope and invariants

The existing pure `ThumbnailBindingPolicy.kt` remains unchanged. `chooseThumbnailStage` chooses memory/placeholder during gestures, unsettled cells, or when sharp content is already visible; a settled cell with a preview requests sharpening, otherwise it requests visible decode. Completion admission is **only** `accessCurrentlyGranted && current == completed && catalogueEpoch >= 0 && sequence >= 0`. It does not enumerate the library, issue decode requests, check provider grants itself, or enforce ticket creation at an integration boundary.

A consumer must obtain the **current** visible-cell ticket and live access-grant flag at completion time. In particular, canceling a decoder is best-effort and must not be treated as successful stale-result rejection. A recycled slot, changed identity (including media type and volume), newer catalogue epoch, superseding sequence, missing live ticket, negative token, or revoked grant must prevent publishing an old bitmap. Equality of the whole ticket is important; identity by bare numeric ID is insufficient.

## Deterministic checks

`ThumbnailBindingPolicyScaleTest.kt` provides:

- All 16 Boolean gesture/settled/preview/sharp combinations against an independently stated stage precedence.
- Valid ticket, null current ticket, permission revocation, slot recycle, changed media ID/type/volume, epoch advance, sequence advance, negative completed epoch or sequence, and valid zero counters.
- A direct parity oracle against the existing admission expression for every pair from a small deterministic candidate matrix and both grant values.
- 250,000 synthetic completion events over exactly 12 live visible-cell tickets, cycling slot indices and monotonically changing sequence; every new binding is accepted while the previous binding for that slot is stale. Periodic revoked-grant completions are refused. The test uses a fixed 12-entry array, not a catalogue-sized map or array of tickets.

Synthetic IDs/URIs are generated by the test and are not sourced from a phone, MediaStore, or personal files. This proof exercises **policy result admission**; it does not benchmark Coil, Compose, cancellation, bitmap allocation, or end-to-end UI frame latency.

## Resource and measurement statement

Live *ticket storage in the test harness* is O(visible cells) = 12 entries, even with 250,000 sequential completions. Each loop iteration constructs only a transient candidate ticket/identity, and the harness does not retain the full synthetic library. This is a structural bound on the test harness, not an assertion that the production integrator currently uses that exact state layout. The 250k loop is O(library completions) total work and does not imply constant total execution time.

No reproducible before/after allocation measurement or p50/p95 latency measurement was made. No CPU, memory, jank, phone responsiveness, or real-device improvement is claimed. The production policy has not been optimized; this change is deliberately test-only unless CI or independent review demonstrates a contract defect.
