# COVER-1 — on-device expression and aesthetics feasibility

Issue [#165](https://github.com/LPStruiksma/atlas-gallery/issues/165), parent [#163](https://github.com/LPStruiksma/atlas-gallery/issues/163). Research snapshot: atlas-gallery `main` [115f9ad9f11140cd770f5fc1634a34d7353d258a](https://github.com/LPStruiksma/atlas-gallery/commit/115f9ad9f11140cd770f5fc1634a34d7353d258a). This is a **feasibility and evaluation specification, not a completed human-preference benchmark**. No photographs, labels, trained weights, or private biometric data are committed. No emulator was run in this research turn.

## Decision

**Ship COVER-2 against COVER-0's technical-quality score first.** Leave an optional, strictly within-person, *small bounded* expression bonus behind a separately versioned, benchmarked gate. Do not infer smiling or eyes-open status from YuNet's five points alone. Do not automatically make a SigLIP aesthetics head the default until it beats the same-person quality-only baseline on held-out, redistributable evaluation data. Do not ship either official SER-FIQ or CR-FIQA checkpoint by default: their published project licences are non-commercial, and their objective is recognition utility rather than the user's subjective favourite photograph.

## Candidate feasibility and evidence table

Size = incremental APK weight/model bytes, not RAM. Latency = additional **per-face** warm model inference, except where explicitly stated. A zero-cost reuse claim holds only when the same image embedding has *already* been computed and is available in the scoring path; computing SigLIP for a face crop is not free.

**Existing emulator baseline, not COVER-1 measurement.** The repository's [VS-B1 API 35 emulator benchmark](../visual-search/VS_B_BENCHMARKS.md) measured YuNet (0.2 MB, 1-thread warm p50/p95 35/42 ms) and SigLIP 2 int8 (98.1 MiB nominal MB in VS-B1's table, 1-thread warm p50/p95 463/470 ms), 5 measured repetitions each, on a 2-vCPU x86_64 emulator. The actual bundled SigLIP graph is **102,869,345 bytes** ([SOURCE.md](../../app/src/main/assets/models/siglip2/SOURCE.md)); VS-B1's 98.1 MB is its rounded binary-size presentation. These are *whole image-tower runs*, **not** a measured latency of any proposed expression/aesthetics candidate. No extra SigLIP run should occur for every candidate face just to rank covers. The existing [SiglipImageEmbedder](../../app/src/main/java/nl/atlas/gallery/featurevisual/onnx/SiglipImageEmbedder.kt) produces an L2-normalised 768-vector, but its default input is the **entire photo**, so it is not necessarily face-specific in group shots; the result can also be absent from an unindexed media item. The existing [YuNetDecoder](../../app/src/main/java/nl/atlas/gallery/featureface/onnx/YuNetDecoder.kt) exposes eyes, nose and mouth corners, not eyelid/smile probabilities.

## Public-data and reproducibility gate (before asserting any accuracy)

1. **Licensing:** choose a public dataset where *individual images and the annotation use* are explicitly licensed for the evaluation. Record URL, per-image licence, author attribution, permitted derivative use, stable splits, SHA-256 of metadata and number of missing images. [AVA](https://github.com/ylogx/aesthetics/blob/master/data/ava/README.txt) is **not automatically an acceptable image source**: it says photographers/dpchallenge retain image rights, and it does not provide the photos. Open Images CC BY 2.0 images, already used by [PEOPLE_BENCH.md](PEOPLE_BENCH.md), can supply legally filtered *images*, but they do **not** supply same-person flattering-shot preference labels. Never turn Flickr author IDs into identity ground truth.
2. **Human ranking:** create a publicly reusable, consented pairwise preference annotation set over *two images of the same consenting subject* (or a dataset explicitly licensed for this task). This is not cross-person attractiveness prediction. Keep images out of the repo unless redistribution is permitted. Include stills and licensed video frames. Split **by subject**, and preferably by photographer/session as well; fit weights exclusively on train, choose thresholds on validation, report final test once. Balance lighting, age range and camera type, and disclose subject-coverage limitations.
3. **Pairwise accuracy:** for each non-tied test pair with an agreed human winner, score both images with the exact COVER-2 eligibility floor and candidate. Report correct / eligible scored comparisons; tie policy (model ties count 0.5, human ties excluded and disclosed); bootstrap 95% confidence intervals **clustered by subject**, not photograph. Report number of subjects, pairs, agreement between independent annotators and exclusions; macro-average accuracy by subject to prevent one prolific subject dominating. Pre-register comparisons against COVER-0 only, addition of expression, addition of SigLIP head, and their combination. Include a deterministic quality-only baseline and a shuffled-label chance control.
4. **Runtime:** run synthetic emulator instrumentation for cold load, warm p50/p95 for 1 and 4 threads, peak RSS, absolute added model bytes, preprocessing/crop and per-face inference cost. For the reused SigLIP path, record fraction of candidate photos with existing valid `siglip2_b16_224.int8:74da3ac2b46e` vectors, and whole-image versus face-crop disagreement on multi-face images. Track 0 extra graph runs only if vectors are truly reused. Keep emulator observations separate from host and handset observations.
5. **Acceptance:** prefer the simplest addition only if subject-macro pairwise accuracy improves by at least **3 percentage points** over COVER-0 on held-out subjects, its subject-clustered 95% CI lower bound is >0, and its added p95 processing cost stays under **20 ms per scored face** *on the specified emulator*, with no increased false or discriminatory rejection of faces. These are **proposed gates**, not measured achievements; Strategy may revise them before training. Any new weight >20 MB must be escalated to Strategy. With insufficient labels or incompatible licences, leave the expression/aesthetics weight at zero.

## Suggested COVER-2 formula (untrained, versioned)

Apply the COVER-0 eligibility floor first (sufficient face size, sharpness, exposure, pose, unobstructed face), then rank **only images of that person**:

```text
if !eligible(face): reject
base = clamp(COVER0_quality_vN(face), 0, 1)
expression = clamp(calibrated_expression_vM(face), 0, 1) // only after benchmark gate
aesthetic = clamp(calibrated_face_specific_head_vK(face), 0, 1) // only if existing suitable embedding
score = base + enabled_expression_weight * (expression - 0.5)
             + enabled_aesthetic_weight * (aesthetic - 0.5)
```

Set **both optional weights to 0.0 until validated**. If enabled later, constrain each weight to ≤0.10, require an available calibrated score or use a consistently defined missing-signal fallback, and persist all score/model versions. Avoid penalising non-smiling or neutral expressions by default; let the user override the result and restore automatic. Pick video frames by the same eligibility and score rule, using stable media/frame IDs. For dynamically arriving better shots, require the candidate to exceed the incumbent by an independently tuned hysteresis margin, and never allow a minor signal bonus to rescue a failed technical-quality floor.

## Completion status

The feasibility/licence and existing-model-cost comparison above are **completed research**. **Benchmark acceptance remains open**: no trained expression classifier, no licensed preference-pair dataset, no COVER-1 emulator candidate run and hence no observed human pairwise accuracy. The table intentionally marks all four unknowns rather than inventing numbers. COVER-2 may safely use COVER-0 without waiting; product-quality claims for expression or aesthetics cannot be made until the measurement gate is fulfilled.
