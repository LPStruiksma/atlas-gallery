## Boundary and audit method

The approved [OWNER_INTENT](https://github.com/LPStruiksma/atlas-gallery/blob/747cfea3becb62192234fa96f839220cc10d6e48/docs/OWNER_INTENT.md) keeps Samsung **feature and in-feature behaviour** parity, but gives ATLAS its own structure and visual identity. These are **code-observed design deltas**, not reports of visual defects reproduced on a phone. For each present surface I compared current Compose styling / UI strings with v3's single lapis accent, system light/dark colours, Funnel type, 8/22/24 dp radius vocabulary, 48 dp targets, held-sphere current/selection/loading states, plain counts and user-driven **Lift** (200 ms, cuts with remove-animations). Current generic `MaterialTheme` colours/typography may inherit L2 later; the delta is **not** an instruction to hard-code duplicate hex colours.

**Excluded as already assigned:** L2 token/font infrastructure (`AtlasTokens.kt`, theme), L3 icon/splash, L4 two-place navigation slab/sphere, L5 **Collections index** (`AtlasAlbumsScreen.kt`), L6 atlas pull-down, L7 expanding search bar, L8 Pictures justified day grid and zoom. The source tree still contains old components pending those units; this audit does not create a second competing implementation. Some child screens currently reuse or enter through those parent surfaces.

**Legend:** L2 = **Yes** means this UI unit waits for L2 tokens/fonts (and later parent unit where noted). "UI brief" = independent design preflight + exact-head synthetic light/dark renders needed **before implementation**, not needed for this document-only audit. V01–V17 below are **proposed IDs, not filed issues**. Each row is a distinct visible screen or reusable UI surface; a group ID intentionally repeats where several surfaces are implemented together.

## Explicit state and interaction checks for future UI briefs

1. **Visual contract:** light/dark, font scale and 48 dp touch-target evidence; primary content is photographs; no second accent, thin lapis outlines, tinted-grey substitutes, middle-dot metadata or circle people-cover grids. Treat error/destructive semantic colour separately from branding where Android/system semantics require it; check actual contrast.
2. **Sphere contract:** selection has a lapis-filled sphere and 2 dp white halo (ordered picks show number); current viewer photo uses a small `#8C9BFF` sphere above the filmstrip plus white ring; loading uses an arc-travel sphere and plain count. Never fake real progress when it is indeterminate.
3. **Motion contract:** 200 ms lift **on deliberate pick**, no autonomous decorative pulsing or shimmers, immediate cut under system remove-animations; preserve swipe, playback, editor, review and data-safety outcomes.
4. **Accessibility/privacy:** screen-reader choice labels and live status announcements remain, Android sharesheet/editor/notification layouts remain OS-owned, no personal photos or embeddings in screenshots/CI, synthetic-only before/after proof.
5. **Coverage edge cases:** loading/permission/no-media/error, empty folders and search, selection count, confirmation dialogs, People scan states, Stories playback, model download progress, rotation, font-scale and external picker single/multi selection all need state-matrix proof at exact PR head.
