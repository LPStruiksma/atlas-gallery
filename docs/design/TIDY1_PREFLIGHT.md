## Primary task and navigation

From a **real** album, Pictures timeline month, results in the existing full Search, or a Photo DNA similarity group, open that *current result set* as a frozen, source-ordered Declutter deck; review with Keep / Skip / Stage Trash, see **Reviewed n of m** per source/month, and resume later with retained Keeps. In comparison, present candidate photos side by side (or quick flip on narrow space); filing uses existing album actions. The current media is always visible above the actionable row without scrolling.

- **Entry:** existing three-dot overflow in album detail (Collections), month heading/context menu (Pictures), Search results action menu, Photo DNA group action menu. Label: **Review in Declutter**. Do not add global nav, banners or new search. Disabled entry when no eligible MediaStore-backed media, with one-line explanation. Entry snapshots the visible source order, including explicit file-size sort when selected. A monthly filtered Search uses both source key and month key.
- **Deck:** secondary full-screen route with back (safe exit), source title and progress line at top; photo/video or poster is visual focus; current position is supplementary. Bottom 48 dp minimum controls: **Keep**, **Skip**, **Stage Trash**. Swipe right = Keep; swipe left = Stage Trash; Skip is an explicit button (not a permanent decision). Undo the last action; review the staged list via visible count. No destructive action on a swipe. Pre-existing delayed media decode/player lifecycle is retained.
- **Resume:** revisiting an identical canonical scope with saved decisions gives a restrained bottom sheet: **Resume review** / **Start again** / **Not now**. Starting again clears this source's progress only after confirmation, not photos; leave and reroute do not silently remove durable Keep decisions.
- **Compare:** only for an explicit similarity set. Two candidates visible at once; on narrow widths offer quick flip with an always-visible compare target. A single shared zoom level and pan coordinate apply to both when image sizes permit; a clear reset restores framing. A **Suggested** label is shown only when an already-available, calibrated quality score supports an order; otherwise use **No suggestion** and source order. The score is advisory, never picks for the user. Explicit **Keep selected** and **Keep both** options; users can Keep more than one. Stage Trash remains an independent, reversible choice on individually selected candidates.
- **File:** under the current photo, a bounded strip of recent albums (up to 4, ordered by real recent use, not guessed affinity) plus **More albums** opens the existing album chooser. Explicit **Move** or **Copy** using existing album operations and permissions; no implicit physical move. A successful filing refreshes/invalidates the affected frozen scope and offers rebuild; it cannot turn an earlier staged snapshot into a trusted Trash request.
- **Trash:** tap staged count, review distinct items, unstage individually, then ATLAS confirmation -> background MediaStore re-query of exact id, name, folder, bytes, nonzero modification timestamp, non-trashed status and distinct URIs -> separate Android recoverable Trash dialog. Keep the 1–200 batch cap, Android 10 prohibition, and session-generation cancellation. On verification failure, exit to fresh review; never "best effort" delete. The app must not suggest that estimated bytes are freed immediately.

## State/identity contract

- **Persist only positive, non-destructive review decisions**: local, private per-source/month Keep identifiers and a stable scope fingerprint. Never persist a staged Trash queue, OS request or confirmation flag. Skip is not durable. Persist no thumbnails/face embeddings. A URI removed, edited, moved, or no longer granted access does not produce an automatic Keep, move or Trash action.
- **Progress:** numerator = current eligible frozen-source items positively Kept; denominator = current eligible frozen-source items. Staged-but-unapproved and Skip are separate, not durable reviewed. Confirmed Android Trash exits the frozen deck and rebuilds the catalogue; now-absent items leave the next snapshot's denominator rather than contributing a phantom numerator. Show confirmed Trash totals only as a separate session result. On source refresh, rebase saved Keep only for items still resolvable with matching immutable-enough metadata and permission; recompute denominator; disclose changed counts rather than fake prior snapshot exactness. Key source identity by canonical source kind/id/filter/sort and optional month bucket (with versioned schema); shared media appearing in two sources is recorded per source, not double-counted in any global total.
- **Resume:** start at first eligible *unreviewed* item in current source sort. A kept file stays reviewed only when identity checks still match; a skipped or formerly staged item reappears. Reordered source keeps decisions by identity but recomputes its position. Never silently resurrect a failed or canceled stage decision.
- **Permissions:** partial media access excludes inaccessible items from deck and explains the restricted scope. Permission revoked during deck disables action and gives **Review permissions** / **Back**. Android 10 can Keep/Skip/Compare/File when supported, but Stage Trash's final commit is disabled with plain copy. Permission denied in album Move/Copy preserves original and provides retry.
- **Empty/large/loading/error:** empty scope: "No photos to review here." / "Back to album"; completed scope: "All 480 items reviewed." / "Back to collection"; indexing/verification: held sphere beside numeric count and disabled mutation controls; long catalogs (150k): lazy, cancelable prefetch with no eager decode or one-player-per-card; no matches in Search preserves Search query/return affordance; changed source during verification: "Items changed. Start a new review." Android Back cancels transient sheet first, then exits deck without Trash.
- **Insets/IME/accessibility:** 1080 × 2340 px target = 360 × 780 dp logical; synthetic safe top 24 dp and bottom 24 dp (actual insets measured later). Primary actions above bottom system inset, all targets >=48 dp, reachability near thumb; no deck keyboard. Search opens the existing keyboard above its slab, and entry menu dismisses IME before opening deck. TalkBack reads current media position, reviewed count, staged count, swipe alternatives and suggested-score disclaimer. Font scale 200%, landscape, RTL and reduced motion must not hide decisions; no automatic animation. Light/dark approved Quiet Frame tokens with sufficient contrast, no new palette.
- **S24+ frames:** these are generated **1080 × 2340 SVG vector wireframes**, each source drawing fills the exact viewport; annotations, imagery and status are illustrative, not screenshots. [Entry light](docs/design/evidence/tidy1-rev1/entry-light.svg) / [dark](docs/design/evidence/tidy1-rev1/entry-dark.svg), [Deck light](docs/design/evidence/tidy1-rev1/deck-light.svg) / [dark](docs/design/evidence/tidy1-rev1/deck-dark.svg), [Resume light](docs/design/evidence/tidy1-rev1/resume-light.svg) / [dark](docs/design/evidence/tidy1-rev1/resume-dark.svg), [Compare light](docs/design/evidence/tidy1-rev1/compare-light.svg) / [dark](docs/design/evidence/tidy1-rev1/compare-dark.svg), [File light](docs/design/evidence/tidy1-rev1/filing-light.svg) / [dark](docs/design/evidence/tidy1-rev1/filing-dark.svg), [Confirm light](docs/design/evidence/tidy1-rev1/confirm-light.svg) / [dark](docs/design/evidence/tidy1-rev1/confirm-dark.svg). ## Reference decision record (2026-11-21; no private screenshots)

| Device/screen | Observed documentary signal | Proposed ATLAS adaptation | Deliberate difference / limits |
| --- | --- | --- | --- |
| Android Material 3 [bottom sheets](https://developer.android.com/develop/ui/compose/components/bottom-sheets) | Official Android documented modal sheet pattern; no claim of how Slidebox renders it | Resume and album choice sheet under still-identifiable photo | Tiny number of choices, visible photo retained; sheet placement is a proposal, not measured S24 behavior |
| Material 3 [search bar](https://developer.android.com/develop/ui/compose/components/search-bar) + [ATLAS Search](../../app/src/main/java/nl/atlas/gallery/featuresearch/AtlasSearch.kt) | Expandable search pattern and existing shared search source code | Deck entry in existing Search results overflow; return to original query | No new search UI, no assertion about Samsung's positions |
| [ATLAS Declutter Studio](../DECLUTTER_STUDIO.md) | Current documented Keep/right, Stage Trash/left, undo, preflight and separate OS approval | Extend source scopes and durable *non-destructive* Keep only | **Do not** persist a pending Trash decision; new Skip button is distinct |
| [Apple Photos: review more photos (Mac)](https://support.apple.com/en-asia/guide/photos/phtad9d981ab/mac) | Documented sequential Yes/Not review on Mac | One-photo-at-a-time decision focus | Platform differs; no claim of Android gesture equivalence |
| Slidebox, Swipewipe, Google Photos | Named in [#577](https://github.com/LPStruiksma/atlas-gallery/issues/577) as product inspiration; specific versions/placements **not independently verified here** | High-level, one-thumb triage objective only | No copied card or behavior claims; actual layout comes from Quiet Frame |

**Identity:** [Quiet Frame v3](QUIET_FRAME.md) is the sole UI spec: white/black ground, mist/surface, lapis fill/text, Funnel Display/Sans, 24 dp slab corners, 8/22 dp secondary radii, 48 dp targets. The held sphere marks the current selected comparison photo and active media in filmstrip; loading uses sphere-on-arc beside a plain count. The secondary Declutter route does not add a third bottom place or second nav bar. Viewer media ground remains black. Actual font metrics, contrast compositions, tap bounds and light/dark exact-head renders must be independently verified in implementation.

## Implementation units and proof (not implemented in this PR)

**TIDY-1A (first Dev slice, non-destructive):** source adapter + canonical scope/sort + durable Keep/Skip/progress/resume + all 4 entry points. Needs: run:android. UI: yes. Done: source-order tests (album/month/search/Photo DNA/file size), month/source overlap and changed metadata tests, 150k lazy performance, process restart Keep retained, Skip/stage not retained, verified permission fallbacks, rendered entry/deck/resume pairs.

**TIDY-1B (after 1A):** compare and album filing controls. Needs: run:android. UI: yes. Touches: Photo DNA grouping/quality signal reader (quality signal may be unavailable: fallback), compare gestures, existing album operation APIs, tests. No dependency on draft quality-score PR [#738](https://github.com/LPStruiksma/atlas-gallery/pull/738).

Done: JVM and emulator confirm/cancel/mutation tests, 200 boundary, Android 10, stale session, scoped permission revocation, no delete during preflight, two confirmations; *no OS Trash run on personal media*.
