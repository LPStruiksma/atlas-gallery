## 1. Provider admission: prerequisites are not proof

Primary references: [Android shared media guide](https://developer.android.com/training/data-storage/shared/media), [MediaStore API](https://developer.android.com/reference/android/provider/MediaStore), [MediaColumns](https://developer.android.com/reference/android/provider/MediaStore.MediaColumns), [Android 14 partial access](https://developer.android.com/about/versions/14/changes/partial-photo-video-access), [DocumentsContract](https://developer.android.com/reference/android/provider/DocumentsContract), [ExifInterface](https://developer.android.com/reference/androidx/exifinterface/media/ExifInterface). These describe access and metadata operations, not crash-safe conditional replacement. Opening a writable descriptor, calling saveAttributes, renaming or using a pending row is not evidence that an existing original can be atomically replaced while preserving its identity. Do not use a truncate/write sequence, delete/reinsert, rename swap, or ordinary update plus file write as a transaction.

| API | Local app-owned MediaStore single-image JPEG | Foreign-owned MediaStore single-image JPEG | Other providers |
| --- | --- | --- | --- |
| 29 | Ownership may permit access; default no write | Investigate RecoverableSecurityException and exact grant scope; default no write | No write |
| 30–32 | Generation/version available for detection, not locking; no write | createWriteRequest (30+) for specific item URI consent; no write | No write |
| 33–35 | Read/media grant and version prerequisites; no write | Granular read grant (33), selected-media grant (34+) as applicable, separate item write consent; no write | No write |
| 36 | Same checks; exact device/provider proof required; no write | Same checks, no blanket authorization; no write | No write |

Every row is further partitioned by exact API/build/provider implementation, ownership, primary/removable volume, personal/work profile, local/cloud/OEM-managed storage, pending/trashed/normal row, grant state and MIME/actual container. Only an ordinary, readable, normal, single-image JPEG on local primary storage in personal profile is a *first investigation candidate*, not a supported write cell. App-owned and foreign-owned evidence is separate. Removable storage, work profile, pending/trashed rows, cloud-backed/OEM providers, SAF/other content providers and Samsung devices without exact synthetic evidence are unknown/no write. Missing identity, unavailable volume, revoked read/write, expired consent, malformed or redacted bytes, unsupported MIME or mismatched signature likewise no write. PNG, WebP, HEIC/AVIF, RAW, motion/animated images, video, opaque containers and unidentified segments unsupported. No cell inherits evidence from another; absent API/device evidence is recorded unavailable, not passed.

Android 10+ may allow app-owned media operations without a storage permission; neither ownership nor consent is an atomicity guarantee. For foreign media, ACCESS_MEDIA_LOCATION runtime consent and setRequireOriginal (API 29+) are prerequisites to investigate unredacted reads; missing permission, inaccessible original or unproven #579 means Unknown, not absent. API 30+ getVersion/getGeneration and GENERATION_ADDED/MODIFIED are change detection, not compare-and-replace. createWriteRequest authorizes writes on named URIs, not an item version or lock. Verify exact grant lifetime on the target API; grant alone cannot establish the safety window. Do not request elevated permissions here.

## 2. Three independent invariants and admission

* **Bytes:** full original stream SHA-256 and length before staging; cancel and any precommit failure leave identical bytes. Undo restores those exact prior bytes, not a re-encoded approximation.
* **Image and protected metadata:** independently compare encoded scan/entropy stream and decoded pixels, dimensions, orientation, embedded thumbnail/previews and every non-target metadata carrier, including AI provenance, camera settings and color profile. Success changes only explicitly intended metadata and necessary structural lengths/offsets; never silently re-encode. If a location carrier inside a protected thumbnail or opaque segment cannot be safely reconciled, reject. Preserve capture-time semantics unless explicitly edited.
* **Provider state:** separately record row identity, size, date taken, date modified, generation, volume version and visibility. Success verifies expected row and projection; undo reports which provider fields differ (generation and modified time are provider-controlled). Exact bytes do not imply restored provider revision. Never promise exact restoration of the provider clock/generation.

An atomic conditional commit must ensure no observer can see partial bytes or a failed/cancelled mutation. A kill after an indivisible successful commit is an interrupted success awaiting reconciliation, not a reported cancellation. Backup is not atomicity; repeated reads are not race exclusion. Demonstrate conditional replacement bound to a stable row identity plus byte/version precondition, or equivalent exclusion of concurrent provider/other-app writes through commit and verified publication. Also demonstrate atomic restoration. If impossible or unproven, keep original read-only. Offer a separately scoped, explicit copy-only proposal, never silently substitute it.

## 3. Future transaction and recovery (not an implementation)

1. Read exact specific-volume URI, authority, profile, row ID, media kind, volume/version, generation-added and generation-modified where available, size, modified time and full unredacted hash; validate container. Bind preview/draft to that tuple. Unknown/duplicate/inaccessible identity fails closed. Draft lives privately and changes no original/index. Cancel/discard before commit is no-op on original, remove staging.
2. Before asking for edit consent, explain exact requested changes, temporary backup and hard expiry even if recovery unresolved; require explicit acceptance. Stage original and separately constructed candidate in app-private no-backup directory; validate all three invariants against candidate, record expected post-hash and expected provider transition. Verify staged bytes and fsync data and durable journal intent (including staging identifiers, transaction state, identity, pre/post hashes and expiry); demonstrate durable directory/rename semantics. No journal/backup means no write.
3. Obtain fresh per-item explicit consent where applicable. Denial, cancellation, revocation or expiry before commit: no write; do not recycle grants after expiry. Re-open and recheck all available identity/version fields and full hash after consent and immediately before commit. Acquire proven provider race-exclusion/conditional replacement, not just another read. Stale revision, replaced/deleted/reinserted row, different volume or profile, unexpected provider reset, or unavailable mechanism: abort; reload explicit draft only on a fresh identity.
4. Only a proven atomic commit may linearize. Reopen original, verify same row and expected post-version, hash, length, parsed metadata, image invariants and provider fields. Durably record verified success before notifying index. No speculative UI or index values. Any mismatch or interrupted uncertain commit sets recovery-needed; no retry or automatic restore. A failed operation must never expose changed/partial bytes; a provider that cannot prove this remains disabled. No success until verified durable journal.
5. On restart or next opening same item, read private journal and show recovery-needed, read-only, with remaining retention. Never write in background or on startup. If same verified identity and bytes match pre-hash, reconcile verified no-change without another write. If expected post-hash and identity match, verify all expected metadata/provider transition and reconcile successful commit, or offer explicit Undo/restore with newly acquired consent and current identity/conditional replacement. Unknown/partial hash, inaccessible original, row reuse or concurrent replacement: preserve private evidence until expiry, report unresolved, never overwrite. Block new edits while unresolved.
6. Undo is another atomic conditional transaction: compare expected post-identity/hash and current grant, stage durable restore intent, obtain fresh explicit consent, recheck, restore original bytes atomically, reopen and verify pre-hash plus protected metadata; record provider fields not restored, durable journal restore, then reconcile index. Failure/kill/revocation leaves recovery-needed, not restored; no auto-retry, blind overwrite or resurrection. Restart reconciles only known verified states. If another app changes original, do not roll it back.

### Bounded private staging

Proposed future design defaults, not authorized implementation: one active transaction/Undo backup total; maximum 256 MiB including original, candidate and journal; sufficient free bytes for both streams plus 32 MiB margin; unknown size, overflow, quota or low free space refuse before any write. Enforce quota while staging and verify actual lengths/hashes; delete partial staging on failure. Maximum 24 hours from initial staging, not from latest open or restart. No extension; demonstrate robust expiry across restart and clock changes (uncertain clock must not extend access). No media, identifying paths, values or hashes in logs, diagnostics, GitHub, share cache, Android backup or export. No keep-both outside private staging.

Closed outcomes: (a) verified atomic restore with fresh consent within window; (b) verified no-change/success reconciliation without another write; (c) explicit user-confirmed private-copy discard with unresolved result and loss of Undo disclosed; (d) hard expiry. Notify promptly, display countdown and block new edits while unresolved. At 24 hours all access to restore/Undo expires even if unresolved. Delete private original/candidate staging and identifying journal data on first permitted cleanup execution (immediately if running; otherwise before use on next startup); do not claim physical deletion while stopped. Cleanup failure remains inaccessible, blocks further staging and retries cleanup on next permitted execution; no export/extension or original write. Keep only minimal local non-media unresolved-status information until acknowledgement, no claim of restored/success; uncertainty does not unlock original editing of that item until independently reconciled (if item cannot be safely rebound, keep original edits disabled). On deletion never resurrect; purge resolved backup on deletion, discard or expiry. App-data clear/uninstall loses recovery copy and journal; disclose before edit, never rely on it for durable provider atomicity. If safe expiry/cleanup and recovery cannot coexist, disable original edit.

## 4. Canonical location-field contract (A and D, independent of write verdict)

This section applies even with D NO ORIGINAL EDIT. Sources: [CIPA EXIF standards](https://www.cipa.jp/e/std/std-sec.html), [ExifInterface tags and XMP caveat](https://developer.android.com/reference/androidx/exifinterface/media/ExifInterface), [Adobe XMP storage specs](https://github.com/adobe/XMP-Toolkit-SDK/tree/main/docs), [IPTC Photo Metadata 2025.1](https://www.iptc.org/std/photometadata/specification/IPTC-PhotoMetadata-2025.1.html). No actual coordinate examples. Inventory includes duplicates, alternate encodings and nested carriers, not just what the viewer displays.

| Carrier (first investigation: ordinary JPEG) | Required inventory/removal/readback |
| --- | --- |
| APP1 EXIF/TIFF GPS IFD | GPS pointer and entire IFD, tags 0x0000–0x001F: version, latitude and reference, longitude and reference, altitude and reference, timestamp, satellites, status, measure mode, DOP, speed/ref, track/ref, image direction/ref, map datum, destination latitude/ref, longitude/ref, bearing/ref, distance/ref, processing method, area information, date stamp, differential, horizontal positioning error. Check all IFDs and nested EXIF, duplicate APP1, orphan data and unknown future GPS tags; remove all location data and pointers with verified no residual bytes. |
| XMP | Standard APP1 and extended APP1 chunks (assemble by identifier, length and offset), TIFF tag 700 and duplicate packets; EXIF/exifEX GPS properties including destination, timestamps, altitude, direction and refs; IPTC Core/Extension and Photoshop location properties, structured LocationCreated/LocationShown, sublocation, city, province/state, country/code, identifiers and coordinate children. Inspect all namespaces, arrays and nested structures; malformed/unknown location semantics fail closed. |
| IPTC IIM / Photoshop APP13 IRB | Location content including city, sublocation, province/state, country code/name, content location codes/names and all duplicated XMP equivalents; parse all resource blocks, reject unknown opaque resources. |
| Embedded images / opaque | IFD1 thumbnails, APP0/JFXX, previews, MPF, MakerNotes, comments, unknown APP segments, trailing bytes, arbitrary metadata blobs: inventory every segment and nested image; reject if not independently interpretable and removable without violating protected bytes. Motion/MPF and other multi-image containers unsupported. Free text/opaque carriers that could encode location cannot be asserted clean. |
| Other formats | HEIC/AVIF item properties/EXIF/XMP, PNG chunks, WebP RIFF chunks, RAW, video/QuickTime location atoms (including ISO 6709 representations), motion/animated formats not supported; no claim of stripped location. Future per-format full carrier inventory and independent parser required. |

Use structural walk of complete JPEG (SOI to EOI and trailing bytes), lengths/offsets, allowed markers, nested metadata and all duplicate segments; parse candidate with an independent reader plus independent segment/byte audit (not the same writer's in-memory tags). Reject malformed, overlapping offsets, unrecognized/opaque data, duplicate contradictory values and unverifiable carriers. Known absence requires affirmative complete readback, not a null field, redacted stream, failed read or EXIF-only check. D set/replace only named capture-point fields, validate finite signed latitude within 90 degrees north/south and longitude within 180 degrees east/west, consistent hemisphere/reference and rational encoding, no implicit zero (zero is valid only when explicitly entered). Proposed input precision up to six decimal places, round once and show same persisted value; reject unsupported precision rather than silently move point. Altitude optional finite value with consistent above/below reference; reject invalid/nonfinite values. Explicit Remove removes every covered location carrier, including ancillary GPS fields; never conflate with Unknown. If protected non-target data cannot be preserved while removing location, D refuses the edit.

A Share Remove location **On**: keep On through failure, use only a separately scoped supported temporary derivative whose complete readback proves covered location absent. Even verified no-location originals require verified derivative; do not dispatch original URI. Non-JPEG (including HEIC/video), opaque/unknown/redacted/unverified input or output: unsupported/Cancel; transient failure Retry/Cancel. No location-free claim, no outbound dispatch or original fallback; a future supported derivative requires its own independent proof. Off is a separate explicit idle user choice in parent v3 state machine, never a fallback or auto-toggle. Contract concerns metadata, not visual clues or a promise of anonymity.

## 5. Capture date and offline point entry

For candidate JPEG use EXIF DateTimeOriginal + OffsetTimeOriginal, consistent SubSecTimeOriginal, validate local civil calendar and explicit offset (or named zone resolved at chosen date). For naive timestamps require explicit zone/offset, reject nonexistent DST gaps, require explicit fold choice when two offsets valid. Reject impossible/unrepresentable dates; don't silently adopt device zone or shift wall-clock. Preserve digitized/modified date and unrelated metadata unless a separately scoped change authorizes them. Separately verify MediaStore DATE_TAKEN UTC epoch milliseconds matches chosen instant and is admitted by current timeline policy; DATE_MODIFIED seconds and generation are provider controlled, never user-set capture date or promised restoration. Display before/after civil time, offset and timeline date. GPS timestamp is a distinct UTC observation; do not fabricate it from capture date. No implicit date or coordinate default. Point input is numeric offline; show Map unavailable / coordinate entry, Unknown/read-only when redacted. No tiles, geocoding/network or new offline dataset; #579 owns feasibility and owner network decision.
