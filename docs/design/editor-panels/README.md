# EDIT-10 · Atlas editor tool panels — pre-build design brief

**Unit:** [#728](https://github.com/LPStruiksma/atlas-gallery/issues/728) · **Goal:** [#629](https://github.com/LPStruiksma/atlas-gallery/issues/629) · **Stage:** proposed, independent design preflight pending. **UI: yes** · **Latitude:** fidelity for tool availability, order, semantics and gestures in [EDIT-0](../../editor/PARITY.md), room for appearance under [Quiet Frame v3](../QUIET_FRAME.md). **Needs:** render. **Live check:** S24+ emulator renders and then owner-approved S24+ canary, using synthetic images. **Docs impact:** this directory only.

## Task, intent and boundary

Owner words: “full parity and similar UI and performance” and “uniquely well designed, modern and intuitive yet distinct and immediately visually recognizable as itself” ([owner intent](../../OWNER_INTENT.md)). **Not this:** no Samsung proprietary filters, sticker art, Galaxy AI implementation or assets; no UI split into separate AI Edit / Face Swap editors; no baked changes until explicit Save; no real photos or identity data in shared proof.

One viewer pencil opens **the single Atlas Editor**. A photo remains the focal object throughout choosing a tool, moving a handle, entering text, selecting a mask, previewing an AI candidate, comparing, undoing and saving. The shell of [EDIT-4 #634](https://github.com/LPStruiksma/atlas-gallery/issues/634) owns Back, Undo, Redo, Compare, Save and Save as copy. Tool surfaces are subordinate, **never** a second navigation system or a different history. M2 Transform, M3 Adjust/Filters, M4 Decorate and M5 AI tools are later implementation units, not changes made by this brief.

**Design brief: Transform.** Adjust the framing and geometry while observing the photo: movable crop handles, aspect presets, rotate/flip, straighten, auto-straighten suggestion, horizontal/vertical perspective and free-corner perspective, lasso free/shape crop, two-finger rotate and pinch/pan. Commit a reversible geometry recipe step only when the adjustment is applied.

**Design brief: Adjust.** Alter tone without losing the photo: Auto, brightness, exposure, contrast, highlights, shadows, saturation, hue, white balance/light balance, temperature/tint, RGB/component curves, Color mix H/S/L and eyedropper (at most three user-selected custom colors per Samsung help), spot add/remove/erase. Show detail/sharpness only if the S24+ parity canary verifies it. One active control and its value at a time; neutral/reset must be discoverable, but the exact numeric bounds remain **D** in the ledger.

**Design brief: Filters.** Pick an **Atlas-generated** look from real preview thumbnails, adjust its strength, create a custom filter from a user-selected reference photo, name/edit it, and copy/paste a tone/filter recipe where supported. Never imply Samsung filter artwork/catalogue is included. Use a horizontal, scrollable film of candidate looks with visible current selection.

**Design brief: Decorate.** Draw with pen/highlighter/isolated stroke eraser; place shapes, editable text, system emoji and licensed/user-made sticker layers. Handle positions, rotate/resize, z-order and later re-edit without flattening the original. Text entry calls the system IME but keeps the active text layer identifiable. Stroke eraser does not erase the underlying photograph.

**Design brief: AI tools tray.** Erase by brush or object tap-select with mask refinement; expose shadow/reflection erase only when capabilities exist; portrait blur, cutout, upscale, face restore; and **AI Edit** / **Swap person** entries. These are tools launched from the tray on the **current rendered working image** per [EDIT-5 contract](../../editor/AI_TOOLS.md), not standalone editors. Show provider/route and cost before an explicit Generate if applicable; selection alone never uploads, bills or changes history. Results remain candidates until **Use edit**, then become one undoable recipe operation. Swap person retains local-only identity processing.

## S24+ viewport, navigation and geometry contract

The wireframes [Transform](transform.svg), [Adjust](adjust.svg), [Filters](filters.svg), [Decorate](decorate.svg) and [AI tools](ai-tools.svg) each place **two adjacent full-frame 1080 × 2340 px panels** (light/dark). Each panel uses a **360 × 780 dp planning canvas rendered at ×3** for review readability. **This is a vector design target, not a measured S24+ screenshot or asserted dp density.** The eventual S24+ screenshot must record actual density, status/nav/IME insets, font scale, orientation and viewport usable dp; adapt these design regions accordingly.

| Canvas region, in dp from top | Intended use | Rules |
|---|---|---|
| 0–24 | status / cutout safe area (illustrative) | never place handles or tappable commands under insets |
| 24–80 | shared editor command bar (56 dp) | Back, Undo/Redo, Save; overflow for Save as copy, Revert; Compare remains press-and-hold on image and accessible command |
| 80–516 | flexible **photo stage** | image fit inside available stage; maintain whole-photo context, pinch/pan and handled gestures; no tool deck covers live handle under finger |
| 516–682 | active tool deck | category-specific active controls and secondary drill-down; scroll within deck, not the image; expandable sheet only as needed |
| 682–748 | shared tool picker / category slab | Transform, Adjust, Filters, Decorate, AI tools; horizontally scrollable with text and icons; selected category is visually unmistakable |
| 748–780 | navigation/inset + safe area (illustrative) | target hit rects must remain above gesture region |

**200% text state override (schematic):** in the five `200% font` mini-frames, application commands grow from 12–14sp to 24–28sp and flow onto a second row, leaving Back and Save persistent; status-bar glyphs remain system-scaled. The photo stage is re-fitted between the two-row command header and the scrollable tool deck (still visible), while the primary Apply/Done/Run action stays in a ≥48dp target. The selected category and its neighbors use 22.8sp labels (twice the 11.4sp baseline), 48dp-tall pills and a horizontally clipped/scrollable category film rather than shrinking labels to make five fit. Tool-deck text wraps or moves into vertical overflow, not across the photo. These layouts are *design simulations*, not Android font-scale screenshots; actual font scaling, 48dp touch target bounds, focus order and scroll/reach must be verified in Compose and on S24+.

At minimum **48 dp targets**, 8 dp preview/thumbnail corners, 22 dp secondary surfaces, 24 dp rounded lapis-filled slab. Use **Funnel Display** titles and **Funnel Sans** labels with approved type roles; never invent secondary accents or ad-hoc hexes. Brand token mapping: ground, surface/mist, ink, ink-secondary, brand-fill, brand-text, on-brand, on-brand-secondary and viewer ground all come from [Quiet Frame v3](../QUIET_FRAME.md). Dark uses approved dark tokens rather than transparency-inverted light colors. Held sphere denotes active selection and progress: one lapis sphere, 2 dp white halo if it selects photo content, never a decorative row of circles.

The tool deck is conceptually **below** the image and the contextual control is a part of the **current tool**, not an extra global tab. The center preview is a synthetic landscape on every SVG. Every icon-only action needs an accessibility label; selected controls announce tool + state/value. Haptic/visual feedback may accompany commits but reduced-motion substitutes instant transitions; no autoplays. On loss of capability, show the disabled tool with a concise reason and alternative, never a false active control.

## Panel specifics and interaction sketches

### Transform — M2

Entry → Crop (free) with four 12 dp visual corner grips inside **48 × 48 dp logical hit regions**; the dashed squares in the full-frame Crop views are hit-area annotations, not visible app chrome. Ratio strip (“Free”, “Square”, “4:3”, “16:9”, “More”; **illustrative Atlas choices, verify actual compatibility**) and active Apply/Reset. The tool picker is a horizontally scrollable, named row: Crop, Rotate 90°, Flip, Straighten, Perspective, Lasso. A persistent **More tools** affordance opens a labelled list containing Flip and Lasso even when clipped from the row; no gesture-only discovery. The six appended focus frames show paired light/dark Straighten, Perspective and Lasso states; the Straighten frames also show the labelled numeric angle editor and numeric IME while retaining the photo context. No “New preset” action is part of Transform.

Straighten uses a continuous dial with a centered zero marker and readable live angle, plus an accessible **Angle · degrees** field and −/+ step buttons; the field opens the numeric keyboard, and **Done** commits only the angle entry to the active preview. Auto-straighten is a suggestion with explicit Accept and Dismiss; it is never silently applied. No angle bounds or increments are inferred here. Perspective offers Horizontal, Vertical and Free corners sub-modes; Free corners drags individual vertices while guides and their ≥48 dp logical targets remain visible on the photo. Lasso has explicit Free and Shape modes, a Close path action and visible retained-area shading; the exterior is excluded only when Apply commits the crop.

**Gesture arbitration contract:** at pointer-down, a pointer inside a handle's 48 dp hit region belongs to the nearest eligible handle for that gesture; overlapping regions resolve to the nearest handle, never to photo pan. A one-finger photo pan begins only outside all handle/control regions. Pinch/rotate is recognized only when neither pointer began on a handle or active lasso/control gesture. In Lasso mode, one pointer on the photo owns the path until close/cancel; it cannot change mid-gesture into pan or handle movement. A cancelled/invalid drag restores the previous preview and creates no partial operation. Apply records one reversible geometry step; global Undo/Redo reverse/reinstate it. Reset removes only the active uncommitted adjustment. These are design contracts to validate in Compose instrumentation, not claims that runtime arbitration is already proven.

### Adjust — M3

Entry opens the single Adjust deck with **Auto as the first visible suggestion action**, followed by the horizontally scrollable Light, Colour, Curves, Mix and Spot groups. The proposed organization is Atlas-specific; it does not claim to reproduce a current Samsung tab order. Auto is a suggestion, never an implicit edit: **Accept** stages the suggested tone result inside the current Adjust transaction; **Dismiss** closes the suggestion and leaves the staged preview unchanged. After the suggestion is accepted, Apply is still required to create a recipe/history step.

- **Light:** Brightness, Exposure, Contrast, Highlights, Shadows and Light balance. Show exactly one active slider, its current example value and a discoverable neutral/reset affordance.
- **Colour:** Saturation, Hue, White balance, Temperature and Tint. Show exactly one active slider and its current value; neutral/reset returns that active control to its neutral/default state.
- **Curves:** photograph-visible graph, RGB plus component channels, selected editable point, and explicit Add point / Remove point actions. Point dragging remains a provisional gesture until Apply.
- **Mix:** selected colour with Hue, Saturation and Luminance controls, an eyedropper, and no more than **three** user-sampled custom swatches. When all three slots are occupied, Add sample is unavailable; removing one frees a slot.
- **Spot:** Add, Remove and Brush erase modes. The active brush is drawn as a bounded circle on the photo; the boundary remains visible during touch/drag and the action affects the staged spot adjustment only.

Numeric ranges, increments, units and engine-specific limits remain **D** until sourced from the engine or a canary. Example slider readouts in the SVG demonstrate a value label only; they are not proposed bounds or calibrated S24+ readings.

#### EDIT-14D — Adjust entry, staged transaction and panel-specific states

The matching [Adjust SVG](adjust.svg) contains paired light/dark 360 × 780 dp planning frames (main frames at ×3 = 1080 × 2340 px; focused state frames at ×2 = 720 × 1560 px). All frames retain the same synthetic photo context and use the approved Quiet Frame v3 light/dark tokens. They are proposed vector design evidence, not Android renders, measured S24+ behavior or proof of runtime geometry.

| State | Visible evidence and behavior |
|---|---|
| First entry / Auto | Auto is the first visible suggestion action, before the Light / Colour / Curves / Mix / Spot group strip. Its suggestion has separate **Accept** and **Dismiss** actions. Accept stages one Auto result; Dismiss leaves the preview unchanged. |
| Light slider | Active Exposure slider, example current value, visible neutral value and Reset. The track, thumb and step affordance are touch/drag targets; drag updates only the staged preview. |
| Curves | RGB and component-channel selection, graph with a selected point, and explicit Add point / Remove point affordances. The selected point is draggable; add/remove and drag remain provisional until Apply. |
| Mix | Hue / Saturation / Luminance controls, eyedropper, and exactly three visible custom sampled swatches in the full state. No fourth sample is shown or implied. |
| Spot | Add / Remove / Brush erase mode selection and a visible bounded brush circle over the photo. The brush ring denotes the active affected area; it is not an unbounded gesture or measured device brush size. |

**Three distinct transaction actions are always visible in the normal Adjust deck:**

- **Cancel** discards the current uncommitted Adjust preview and any in-progress gesture, returning to the state before this Adjust transaction. It is not Reset and does not create a history step.
- **Reset** returns only the active control or subtool to its neutral/default state within the current staged transaction. It does not discard the rest of the Adjust preview and is not a synonym for Cancel.
- **Apply** commits the staged Adjust change as **one** recipe/history step, regardless of the number of slider frames or provisional gestures. It is not a Save action. The editor shell remains the sole owner of Save / Save as copy; this panel adds no save path.

The shell Back action never silently commits or discards a pending Adjust transaction. With staged changes present, it first offers **Discard changes** or **Keep editing**; the explicit Cancel action remains available in the deck. After Apply, shell Undo reverses the one committed Adjust history step. Reset and Dismiss do not add history entries.

**Interaction and accessibility annotations apply to every focused state:** focus order is shared shell controls → photo context → Auto suggestion / selected group → active value and control → Cancel → Reset → Apply. Every action and draggable control has a ≥48 dp logical hit area, including slider thumb/step actions, curve point and Add/Remove actions, eyedropper and swatch actions, Spot mode buttons and the bounded brush target. Sliders and points support touch/drag with a visible active value/selection; the photo remains visible above the deck while editing and is not obscured by an expanded picker. At 200% font, labels wrap or move into a vertically scrollable deck, the action row can grow to two lines while preserving ≥48 dp targets, and a meaningful photo anchor remains visible; no labels are shrunk or clipped to keep all groups on one line. Actual TalkBack traversal, logical hit rectangles, font scaling, insets and reach must still be validated in Compose and on the later S24+ canary.


### Filters — M3

Entry → a horizontal row of synthetic filter *photo thumbnails* showing “Original” first, chosen Atlas LUT options afterward, and a held-sphere current indicator; no proprietary Samsung art. A chosen look opens Strength and a reset affordance. “From photo” launches a scoped system photo picker (user-selected reference only) and offers “Name filter” before adding to user filters. Copy/Paste recipes live in panel overflow; unavailable paste states explain why. Filter strength numeric units are unknown until engine/canary. A failure to decode a reference leaves the working edit unchanged and exposes Retry / Choose another photo.

### Decorate — M4

Entry → tool row Pen, Highlighter, Eraser, Shape, Text, Emoji, Sticker, Layers (scroll); selection opens its focused options in the deck. Pen/Highlighter: width and color picker; Eraser affects **only decoration strokes**; Shape: line, arrow, rectangle, ellipse (snap if supported); Text: source-aligned editable box with font/size/alignment/color/background and IME; Emoji: system emoji picker; Sticker: user-made or open-license assets only. Selected objects expose rotate/resize handles **and** larger logical target hit areas, plus layer order (Forward/Back) and Delete; keep handles accessible against both dark and light photos. Re-edit is by tapping a stored layer, even after a previous Save, provided recipe data is preserved.

**Decorate repair contract (#939; schematic/proposed only).** The paired native 1080 × 2340 light/dark frames carry dashed ≥48 × 48 dp logical hit-region outlines (Back, Undo, Redo, Compare, Save, five tools, Layers, Done, four handles). The #939 state cards (IME, photo-present/no layers, long list) sit below the original six variants, are drawn in light only, and the paired frames and state cards in `decorate.svg` are planning evidence, not an Android, Compose, One UI or S24+ render and not measured device geometry. The photo-present/no-decoration-layers state is distinct from “Photo unavailable”: it keeps the photo visible and offers safe **Add text**, **Add shape** and **Start drawing** actions; none commits a layer until the user supplies content. The long Layers state is a vertically scrollable list with selected state, layer name and type, a visible position indicator, and ≥48 dp logical row/reorder targets. **Forward**, **Back** and **Delete** operate on the selected layer; keyboard/TalkBack focus is visibly reinforced. Delete creates one reversible history step, immediately announces the removed layer, and enables shared Undo; Undo restores the layer, its z-order and selection.

The IME is a system inset, **not panel chrome and not saved media**. While it is open, re-fit (do not cover) the photo so the selected text, its handles and the pinned ≥48 dp **Done** action remain above the inset. The first system Back dismisses the IME and preserves the active text layer; a second Back leaves text editing according to the shared editor dirty-state contract. The keyboard outline and its approximately 500 dp planning edge in the SVG are illustrative only; implementation records actual inset geometry.

**Decorate accessibility annotations (proposed).** Every Pen, Highlighter, Eraser, Shape, Text, Emoji, Sticker and Layers tool; every rotate/resize/move handle; every layer row, reorder control, Forward/Back, Delete and Done; and shared Back, Undo, Redo, Compare and Save has a logical hit region of at least **48 × 48 dp**, even when the visible glyph is smaller. The native frames outline the visible tools (Pen, Text, Shape, Emoji, Sticker); Highlighter and Eraser, which sit in the scrolled part of the tool strip, are dimensioned in the “Tool strip scrolled” light and dark cards in `decorate.svg`. At 200% font, controls wrap or scroll without shrinking labels or hiding the photo/selection/Done; focus order is shared Back → Undo → Redo → Compare → Save → photo/selected object and handles → active options/Done → tool film → Layers list and actions. One-handed layout keeps creation, Done and layer actions in the lower reachable deck while retaining the shared Save command at the top. Focus feedback combines the approved brand-filled selection with a non-colour cue (weight/outline/label), and TalkBack announces tool state, layer name/type/position, handle purpose and Undo result. All outlines/surfaces use only the Quiet Frame v3 ground, surface/mist, ink, ink-secondary, brand-fill, brand-text, on-brand and on-brand-secondary tokens; synthetic photograph colours are content, not UI tokens.

### AI tools — M5

Entry → local Erase (Brush/Tap selection), Shadow, Reflection, Portrait blur, Cutout, Upscale, Restore, then **AI Edit** and **Swap person** in the same horizontally scrollable tray/deck. Selection of Erase overlays an editable mask on the *displayed working image*; refine/clear mask and only then Run. AI Edit shows prompt, current-image source, explicit provider/estimated charge/route and Generate. Swap person uses a local identity picker and keeps its consent/route semantics; no identities appear in any shared screenshot. Process: **Select → Prepare/confirm → Processing → Candidate compare → Use edit / Discard → single history step**, never Save or overwrite inside a tool. Errors preserve photo, recipe and existing undo position. Loading uses the held sphere and truthful stage/progress if available, without covering the image. Unknown outcome shows “Check result” / “Try again” only when compatible with provider journal, not blind double-charge.
