## Task, intent and boundary

Owner words: “full parity and similar UI and performance” and “uniquely well designed, modern and intuitive yet distinct and immediately visually recognizable as itself” ([owner intent](../../OWNER_INTENT.md)). **Not this:** no Samsung proprietary filters, sticker art, Galaxy AI implementation or assets; no UI split into separate AI Edit / Face Swap editors; no baked changes until explicit Save; no real photos or identity data in shared proof.

One viewer pencil opens **the single Atlas Editor**. A photo remains the focal object throughout choosing a tool, moving a handle, entering text, selecting a mask, previewing an AI candidate, comparing, undoing and saving. The shell of [EDIT-4 #634](https://github.com/LPStruiksma/atlas-gallery/issues/634) owns Back, Undo, Redo, Compare, Save and Save as copy. Tool surfaces are subordinate, **never** a second navigation system or a different history. M2 Transform, M3 Adjust/Filters, M4 Decorate and M5 AI tools are later implementation units, not changes made by this brief.

**Design brief: Transform.** Adjust the framing and geometry while observing the photo: movable crop handles, aspect presets, rotate/flip, straighten, auto-straighten suggestion, horizontal/vertical perspective and free-corner perspective, lasso free/shape crop, two-finger rotate and pinch/pan. Commit a reversible geometry recipe step only when the adjustment is applied.

**Design brief: Adjust.** Alter tone without losing the photo: Auto, brightness, exposure, contrast, highlights, shadows, saturation, hue, white balance/light balance, temperature/tint, RGB/component curves, Color mix H/S/L and eyedropper (at most three user-selected custom colors per Samsung help), spot add/remove/erase. Show detail/sharpness only if the S24+ parity canary verifies it. One active control and its value at a time; neutral/reset must be discoverable, but the exact numeric bounds remain **D** in the ledger.

**Design brief: Filters.** Pick an **Atlas-generated** look from real preview thumbnails, adjust its strength, create a custom filter from a user-selected reference photo, name/edit it, and copy/paste a tone/filter recipe where supported. Never imply Samsung filter artwork/catalogue is included. Use a horizontal, scrollable film of candidate looks with visible current selection.

**Design brief: Decorate.** Draw with pen/highlighter/isolated stroke eraser; place shapes, editable text, system emoji and licensed/user-made sticker layers. Handle positions, rotate/resize, z-order and later re-edit without flattening the original. Text entry calls the system IME but keeps the active text layer identifiable. Stroke eraser does not erase the underlying photograph.

**Design brief: AI tools tray.** Erase by brush or object tap-select with mask refinement; expose shadow/reflection erase only when capabilities exist; portrait blur, cutout, upscale, face restore; and **AI Edit** / **Swap person** entries. These are tools launched from the tray on the **current rendered working image** per [EDIT-5 contract](../../editor/AI_TOOLS.md), not standalone editors. Show provider/route and cost before an explicit Generate if applicable; selection alone never uploads, bills or changes history. Results remain candidates until **Use edit**, then become one undoable recipe operation. Swap person retains local-only identity processing.

## S24+ viewport, navigation and geometry contract

The wireframes [Transform](transform.svg), [Adjust](adjust.svg), [Filters](filters.svg), [Decorate](decorate.svg) and [AI tools](ai-tools.svg) each place **two adjacent full-frame 1080 × 2340 px panels** (light/dark). Each panel uses a **360 × 780 dp planning canvas rendered at ×3** for review readability. **This is a vector design target, not a measured S24+ screenshot or asserted dp density.** The eventual S24+ screenshot must record actual density, status/nav/IME insets, font scale, orientation and viewport usable dp; adapt these design regions accordingly.

| Canvas region, in dp from top | Intended use | Rules |
|---|---|---|
| 0–24 | status / cutout safe area (illustrative) | never place handles or tappable commands under insets |
| 24–80 | shared editor command bar (56 dp) | Back, Undo/Redo, Save; overflow for Save as copy, Revert; Compare remains press-and-hold on image and accessible command |
| 80–516 | flexible **photo stage** | image fit inside available stage; maintain whole-photo context, pinch/pan and handled gestures; no tool deck covers live handle under finger |
| 516–682 | active tool deck | category-specific active controls and secondary drill-down; scroll within deck, not the image; expandable sheet only as needed |
| 682–748 | shared tool picker / category slab | Transform, Adjust, Filters, Decorate, AI tools; horizontally scrollable with text and icons; selected category is visually unmistakable |
| 748–780 | navigation/inset + safe area (illustrative) | target hit rects must remain above gesture region |

**200% text state override (schematic):** in the five `200% font` mini-frames, application commands grow from 12–14sp to 24–28sp and flow onto a second row, leaving Back and Save persistent; status-bar glyphs remain system-scaled. The photo stage is re-fitted between the two-row command header and the scrollable tool deck (still visible), while the primary Apply/Done/Run action stays in a ≥48dp target. The selected category and its neighbors use 22.8sp labels (twice the 11.4sp baseline), 48dp-tall pills and a horizontally clipped/scrollable category film rather than shrinking labels to make five fit. Tool-deck text wraps or moves into vertical overflow, not across the photo. These layouts are *design simulations*, not Android font-scale screenshots; actual font scaling, 48dp touch target bounds, focus order and scroll/reach must be verified in Compose and on S24+.

At minimum **48 dp targets**, 8 dp preview/thumbnail corners, 22 dp secondary surfaces, 24 dp rounded lapis-filled slab. Use **Funnel Display** titles and **Funnel Sans** labels with approved type roles; never invent secondary accents or ad-hoc hexes. Brand token mapping: ground, surface/mist, ink, ink-secondary, brand-fill, brand-text, on-brand, on-brand-secondary and viewer ground all come from [Quiet Frame v3](../QUIET_FRAME.md). Dark uses approved dark tokens rather than transparency-inverted light colors. Held sphere denotes active selection and progress: one lapis sphere, 2 dp white halo if it selects photo content, never a decorative row of circles.

The tool deck is conceptually **below** the image and the contextual control is a part of the **current tool**, not an extra global tab. The center preview is a synthetic landscape on every SVG. Every icon-only action needs an accessibility label; selected controls announce tool + state/value. Haptic/visual feedback may accompany commits but reduced-motion substitutes instant transitions; no autoplays. On loss of capability, show the disabled tool with a concise reason and alternative, never a false active control.

## Panel specifics and interaction sketches

### Transform — M2

Entry → Crop (free) with four oversized hit regions on corner/edge handles, ratio strip (“Free”, “Square”, “4:3”, “16:9”, “More”; **illustrative Atlas choices, verify actual compatibility**) and active Apply/Reset. Tool row: Crop, Rotate 90°, Flip, Straighten, Perspective, Lasso; overflowing controls are discoverable in the same deck. Straighten uses a continuous dial with a centered zero marker and readable live angle, not fabricated bounds. Perspective offers Horizontal, Vertical and Free corners sub-modes; Free corners drags individual vertices, while guides and handles remain visible on the photo. Double touch rotates the content inside the crop while one-touch handle drag adjusts crop bounds; gesture arbitration must not commit partial operations. Auto-straighten is a suggestion that can be accepted or dismissed, **not silently applied**. Lasso shape/free modes must display the retained area. Apply records the step; global Undo/Redo reverse/reinstate it. Reset removes only the active uncommitted adjustment.

### Adjust — M3

Entry → Auto and a horizontally scrollable row of actual adjustment groups (Light, Colour, Curves, Mix, Spot). Light selects Brightness, Exposure, Contrast, Highlights, Shadows, Light balance; Colour selects Saturation, Hue, White balance, Temperature, Tint; Curves opens a photograph-visible grid with RGB and component chips, explicit point add/remove, and Reset curve; Mix has target color swatches (not arbitrary face circles), Hue/Saturation/Luminance sliders and eyedropper with up to **three custom sampled colors**; Spot permits Add, Remove and Brush erase with visibly bounded brush. Active value and reset sit above the single full-width control. Value ranges, increments, neutral positions, availability and curve constraints are **to be taken from the engine + canary**, not invented here. Cancel reverts uncommitted preview; Apply commits one edit; rapid drag does not build undo history for every frame.

### Filters — M3

Entry → a horizontal row of synthetic filter *photo thumbnails* showing “Original” first, chosen Atlas LUT options afterward, and a held-sphere current indicator; no proprietary Samsung art. A chosen look opens Strength and a reset affordance. “From photo” launches a scoped system photo picker (user-selected reference only) and offers “Name filter” before adding to user filters. Copy/Paste recipes live in panel overflow; unavailable paste states explain why. Filter strength numeric units are unknown until engine/canary. A failure to decode a reference leaves the working edit unchanged and exposes Retry / Choose another photo.

### Decorate — M4

Entry → tool row Pen, Highlighter, Eraser, Shape, Text, Emoji, Sticker, Layers (scroll); selection opens its focused options in the deck. Pen/Highlighter: width and color picker; Eraser affects **only decoration strokes**; Shape: line, arrow, rectangle, ellipse (snap if supported); Text: source-aligned editable box with font/size/alignment/color/background and IME; Emoji: system emoji picker; Sticker: user-made or open-license assets only. Selected objects expose rotate/resize handles **and** larger logical target hit areas, plus layer order (Forward/Back) and Delete; keep handles accessible against both dark and light photos. Re-edit is by tapping a stored layer, even after a previous Save, provided recipe data is preserved.

### AI tools — M5

Entry → local Erase (Brush/Tap selection), Shadow, Reflection, Portrait blur, Cutout, Upscale, Restore, then **AI Edit** and **Swap person** in the same horizontally scrollable tray/deck. Selection of Erase overlays an editable mask on the *displayed working image*; refine/clear mask and only then Run. AI Edit shows prompt, current-image source, explicit provider/estimated charge/route and Generate. Swap person uses a local identity picker and keeps its consent/route semantics; no identities appear in any shared screenshot. Process: **Select → Prepare/confirm → Processing → Candidate compare → Use edit / Discard → single history step**, never Save or overwrite inside a tool. Errors preserve photo, recipe and existing undo position. Loading uses the held sphere and truthful stage/progress if available, without covering the image. Unknown outcome shows “Check result” / “Try again” only when compatible with provider journal, not blind double-charge.

## Required state / accessibility proof matrix — applies to *each* of five panels

| State | Visible composition, safe action and eventual render requirement |
|---|---|
| Light and dark / idle | Paired SVG base frames supplied; actual implementation needs exact-head paired S24+ screenshots of each panel and inspectable token values |
| Empty / no media or no saved presets | Shell cannot edit without selected media: photo slot says “Photo unavailable”; Back remains available; Filters empty user-presets says “No saved filters yet. Create one from a photo.” Decorate empty Layers says “No layers yet. Add text, a shape or a drawing.” AI picker empty says “No local people to choose. Add a person in Collections.” Other panels never fabricate data |
| Loading / progress | Photo remains visible if cached; tool value/selection disabled only while necessary; held-sphere progress plus action-specific message (“Preparing preview”, “Generating edit”), real progress only if known; Cancel when safe |
| Error / retry | One short explanation, Retry and safe Dismiss/Back; keep previous pixels/history; reference-picker failure returns to Filters; geometry invalid handle resets provisional move; provider failure never silently commits a candidate |
| Very large choice set | Horizontal tool strip can scroll and announces position; never render 50 tiny icons; filter library and sticker collection use scoped search/list picker; active tool is still reachable in the deck |
| Compare / Undo / Redo | Press-and-hold stage shows **unchanged media original** in outer editor (temporary, clearly indicated); on release restores working preview; nested AI candidate compare shows **pre-tool working image** instead; global Undo/Redo remain in shell (enabled only when applicable), feedback restores selection without hidden save |
| One-handed reach | Critical active control, Reset/Apply and category tabs in lower reachable deck; 48 dp hits; pan/zoom can move image without accidentally moving handles; focus traverses shell → preview → active tool → categories |
| IME open | For Text or AI prompt, keyboard is an **inset, never part of saved media**: compress image stage to show selected text box/AI mask or candidate context, pin active input/action above IME; Back first dismisses keyboard, second exits active edit. Illustrative planning frame: IME begins ~500 dp; **actual bounds depend on device** |
| 200% font / TalkBack / keyboard navigation | Chips can wrap/scroll; no clipped text, icon-only necessary action has a semantic label, no overlap with nav inset; preserve at least ~200 dp of meaningful preview during expanded panel by collapsing secondary rows, using a focused accessible sheet if needed. Announce slider units/steps, handle location and layer names; provide accessible numeric/step controls if drag inaccessible |
| Rotation / insets / reduce motion | Landscape prioritizes preview + side deck without abandoning shared history, safe under gesture nav and display cutout; reduced-motion uses instant state changes; no auto-sliding deck or surprise tab change |
| Large synthetic image / slow compute | Preview tile is a *placeholder only for wireframes*; actual app uses downsampled visual preview with export-quality backing; no “applied” claim until render/commit proof, no hidden scale loss; device budget per [BUDGETS](../../editor/BUDGETS.md) |

**200% and IME layout priority:** keep photo + currently manipulated object **in the same viewport** as the command to finish or dismiss. At 200% font, tool labels grow with a vertical overflow; the image shrinks but never disappears beneath a picker. For a maximized picker show a compact live photo anchor above it, or decline the picker if it cannot preserve context; test with exact emulator screenshots.
