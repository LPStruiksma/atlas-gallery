## Inspectable wireframe

[**Open 12-frame synthetic S24+ board**](./tags-2-things-s24plus-board.svg)

The board contains 12 annotated full-height frame proposals: A Collections first viewport; B Collections scrolled to Things; C empty Search with keyboard; D Things list; E selected-scope results, light; F selected-scope results, dark; G loading; H partial scan; I complete empty; J unavailable/retry; K 117-category large list; L 200%-font Dutch/keyboard state. A–L are **static SVG wireframes, not Android screenshots**. Vector media sketches are synthetic stand-ins for actual photo thumbnails. Final implementation must use permitted actual local preview images and real-ratio strips. The visual is an inspectable proposal and must never be cited as pre-merge rendered proof.

Each phone frame is 384 × 832 **dp**, presented at **2.8125 px/dp = 1080 × 2340 pixels**; 24 dp status and bottom safe areas are **provisional sketch assumptions**, NOT measured Galaxy S24+ insets. Runtime Compose insets, IME height and 100%/200% font must be measured and checked by a later Dev/Review seat. Board uses Quiet Frame v3 tokens. **A–K screen titles use Funnel Display 700, 38sp / 44sp, −0.03em tracking**; L preserves the same 38/44sp title token at **fontScale 2.0 = 76/88sp**, with base 12–14sp body/section text shown at 24–28sp. A generic SVG viewer can substitute a system font; Compose must be measured with the actual bundled Funnel faces. Tap targets specified at least 48dp, with row height 86dp and searchable list virtualized. Board leaves 16dp side padding and 2dp grid gaps; photo strips use 8dp approved radius in implementation.

## Tap and back journeys (A–F)

1. **From Collections:** A shows the top of the approved collection order. **Things is below this initial fold**, so swipe vertically to B; tap the 86dp Things photo-strip row; D opens at the top. Tap Dog → E. From the visible Things row this is **two taps**; the initial Collections viewport requires a scroll and is **not** advertised as a two-tap path without scrolling. Back from results returns to D with the prior list/scroll; back again returns to the prior Collections scroll, preserving context. Do not move Things above albums/people/places solely for this feature.
2. **From empty Search:** tap the existing bottom search sphere; frame C shows expanded AtlasSearch above its slab/IME and an immediately visible photo-led Things entry at y=138–260dp, with text “Browse photos by what is in them”. Tap Things → D; tap Dog → E. The query is blank; this route does not require typing or scrolling. On entering a Things category, dismiss the IME and keep Back behavior in the same search navigation stack.
3. **Results:** E/F show the existing sort control and scope toggle (This screen / Whole library) with selected facet `Dog ×` in a single short horizontally scrollable row. Facets compose with text/person/date/album via **AND**; unselecting restores the preceding constraints; scope is never silently escalated. The scoped grid uses the shared search results and file-size/date/relevance sorting semantics defined by #175. Video moments open at their tag evidence timestamp. Rows use real local thumbnails, not vector mocks, and don't imply verified semantic truth. Preserve existing Hidden/Secure/grant fences in both covers and counts.
4. **Visual selection:** a selected Thing chip has approved solid lapis fill and a **lapis held sphere on its leading corner with 2dp white halo**, plus a removable × and a TalkBack selected state; no invented accent. Unselected chips are approved surface fill. The bottom slab has the current white pill; do not add decorative page chrome. The chip plus text uses a 48dp visual and active target in the SVG proposal; implementation must keep the same minimum 48dp bound. 48dp minimum on Back, Sort, scope and sphere.
5. **Counts/order:** “Top” is distinct-media hit count descending and stable tag-ID ascending on ties, not model confidence. First show up to five nonzero facets filtered to the active allowed query scope; “More things” searches the full enabled list. Things list K virtualizes up to 117 calibrated enabled tags and provides Search things. The Collections summary count is the union of distinct tagged accessible media, not the sum of rows. Video frame hits deduplicate by media key. If index incomplete, all totals say “found so far”; never invent scan completion.

## Data and ownership boundaries

Consume only the shipped, version-fenced **TAGS-1** local `VisualTagStore` with `TagScope.Library|Media(keys)`; do not rewrite the scorer or fork the index. Use `tags.tsv` labels (Dutch for nl, English fallback) and enabled/on-by-default calibrated IDs only; off-by-default classes like Receipt and City must not be silently presented as verified. Filter every lookup, thumbnail and count by current MediaStore grants and Hidden/Secure exclusions. Page/cache distinct counts and strip covers off the UI thread for 250k media; avoid per-composition full scans or full-list sort while scrolling. An API gap routes back to Strategy; no new code in protected files or competing #658/#660 hosts by assumption.

Target implementation area is **new** `app/src/main/java/nl/atlas/gallery/featuresearch/things/**` plus tests, and only narrow host hooks after BRAND-L5 [#658](https://github.com/LPStruiksma/atlas-gallery/issues/658) and BRAND-L7 [#660](https://github.com/LPStruiksma/atlas-gallery/issues/660) clear their files. Search slots: existing `featuresearch/AtlasSearch.kt` `filtersTool` / `suggestionsTool`; coordinate with [COLLECT-1 #576](https://github.com/LPStruiksma/atlas-gallery/issues/576). **Do not route implementation until [TAGS-1 PR #764](https://github.com/LPStruiksma/atlas-gallery/pull/764) is merged.** After independent preflight PASS, typed `hold` with `Blocked-by:` those outstanding PRs/issues and `Then: next:dev` is required; never leave a ringing `next:*` label while waiting.
