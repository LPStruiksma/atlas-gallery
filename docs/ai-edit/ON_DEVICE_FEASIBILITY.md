# AIE-16 — On-device instruction editing: feasibility and admission gate

**Status: research only / NO-GO for a general local instruction-edit provider today.** Reviewed **2026-11-19 UTC**. Unit [#246](https://github.com/LPStruiksma/atlas-gallery/issues/246), parent [#183](https://github.com/LPStruiksma/atlas-gallery/issues/183). This is a docs-only decision, not a model download, inference run, phone benchmark, deployment approval or license opinion. No paid services, private photos, personal faces or new Android dependencies were used.

**Product invariant:** instruction accuracy and preservation of the original person, face, object and unchanged scene outrank convenience. The user must explicitly choose AI Edit on one selected photo; the existing Samsung/system Edit pencil must not change. Background scanning stays offline. Only a later explicitly selected local provider may work without uploading anything; a remote provider is still chosen separately and is never a silent fallback. See [architecture](ARCHITECTURE.md), [hosted providers](PROVIDERS.md) and [existing local Erase implementation](ON_DEVICE_ERASE.md).

## Decision and evidence standard

1. **Postpone** a general-purpose offline prompt-edit adapter and its implementation spike. None of the reviewed model/runtime pairings has demonstrated accurate, identity-faithful **instruction editing on the target Android device** within acceptable sustained memory, time, energy and thermal bounds. Open weights and a runnable desktop pipeline are not phone proof.
2. **Retain local LaMa Erase** as a distinct already implemented operation: it edits masked pixels only, is not a general instruction editor and has no measured S24+ performance. Its existing host and CI-emulator figures **must not** be represented as phone figures [A0].
3. **Revisit with an evidence-only, zero-spend feasibility experiment** only after a model passes the license, provenance, redistribution, runtime and capacity preflight below. First assess a narrow SD-1.5 inpainting pipeline for masked edits; compare FLUX.2 Klein 4B only if a reproducible Android operator/quantization path and memory budget are shown. Do not treat SD-1.5's text conditioning as reliable free-form instruction following.
4. **Separate the admission decision from implementation.** After the test protocol is run, file a new scoped implementation unit only if every hard gate passes on relevant phones. Otherwise record the failing evidence and continue using user-initiated hosted instruction editing and already supported local Erase.

**Labels used throughout:** **S** = source/model author or runtime documentation (not independently reproduced); **D** = locally documented measurement in this repository, with its stated platform; **I** = transparent calculation or engineering inference; **U** = unknown pending measurement or legal/technical verification. A promotional claim is never a benchmark result. Published desktop GPU figures cannot be extrapolated to mobile NPUs/GPUs, especially not an Exynos device.

**Quantization caveat (I):** the 16/8/4-bit arithmetic above is **parameters × bits / 8**, in decimal GB, not a prediction of downloadable model bytes, VRAM, RAM, fit, supported operators or quality. Some tensors cannot be quantized at those precisions, and K/V, decoder, convolution, embeddings, activations, shaders, compiler caches, image buffers and Android shared-memory accounting add overhead. For a 12 MP RGBA image alone, one decoded pixel buffer is ≈48 MB (I), before copies. There are **no measured on-device inference times, storage footprints or power figures** in this assessment.

**License gate:** open-weight ≠ OSI-open-source ≠ unrestricted APK redistribution. Before a candidate can ship, record immutable upstream revision/weight hashes, exact legal text and notices, distribution/derivative rights, third-party model and tokenizer terms, policy/filter obligations, and a plan to supply required notices. A Research-only or noncommercial right does not authorize an arbitrary consumer release. If uncertain, **NO-GO** and request legal/owner decision through a separate unit; no unapproved publishing or model bundling.

## Smallest defensible synthetic / licensed benchmark corpus

**Before any run**: a manifest identifies every source, origin/license/permission, source SHA-256, dimensions, mask and target instruction; license permits copying, editing and distribution of **both inputs and results**. Prefer locally drawn procedural geometry and explicitly licensed synthetic people. Do **not** place real users' photos, biometric embeddings, scraped faces, private originals or paid-provider outputs in a repository. No real person's identity is needed; synthetic faces are a limited proxy, **not validation of real-person fidelity**.

**Minimum admission corpus:** **24 independent sources** × **2 fixed instructions** = **48 edit trials**, plus **4 no-op/unchanged-source controls**. Partition 8 synthetic landscapes/interiors with background constraints, 8 synthetic objects/text/logos with localized masks and detailed geometry, and 8 *distinct synthetic face identities* (two viewpoint/lighting variants only where provenance supports identity consistency). Tasks include local object modification, appearance edit, scene/lighting prompt, typography and face-preserving clothing/hair/background changes. For each source include source image, edited-area or protected-area mask, expected change rubric, exact instruction, fixed seed when supported, and a rejection/unsupported-capability control. Count **at least 16 face trials** whose instructions explicitly preserve identity.

This is a **feasibility screen, not statistical proof of production generalization**. Never run face recognition on actual private photos for this test. For a candidate without mask semantics, record that fact, mark hard-mask tests unsupported, and evaluate only relevant preservation cases; no silent mask dropping.

**Reproducibility:** freeze exact model revision/weight hashes, runtime commit/build configuration, preprocessing and color space, sampler/steps/seed, output resolution, quantization calibration set (disjoint from 48 trials), prompt text, device power mode, fanless state, thermal baseline, foreground app state and output hashes. Publish the license-cleared input/mask/output pairs or a privacy-safe manifest plus reviewer-accessible synthetic proof. Preserve rejects, timeouts, OOMs and malformed outputs in denominators; never silently retry successful trials to improve rates.

**Scoring (proposed acceptance thresholds, not observed results):** two independent blinded raters judge adherence (instruction met without collateral edits), face consistency and artifacts; adjudicate disagreement with a third rater. Record each verdict and machine-computable score with its original reference. No model-author demo or generic FID/Frechet score substitutes for a source-paired edit.

| Gate | Required measured result; any failure blocks admission |
|---|---|
| **Instruction adherence — priority 1** | ≥44/48 independently judged as meeting the *specific* instruction, with **zero critical unintended edits** (wrong person/object, invented change, missing source) and every declared capability tested. Refusals and unsupported requested features are failures for that capability. |
| **Identity/subject fidelity — priority 2** | For the ≥16 synthetic face-preservation trials: ≥15/16 identity-consistent by both raters after adjudication and **zero severe face swaps/distortions**; preserve distinctive synthetic subject marks. Object and scene preservation judged separately for their unaffected subjects. This small test cannot validate human biometric safety. |
| **Unchanged-region drift** | For **hard-mask** claims, compositing must preserve **every decoded original pixel outside the mask exactly** (zero per-channel delta in the same color space, before lossy re-encoding), with zero mask-coordinate shifts. For soft-mask/unmasked models, disclose non-identity-preservation risk and require ≥90% of trial protected regions to show no material unintended visual change by raters. A provider may not claim hard-mask support from soft conditioning. |
| **Visual quality** | ≥44/48 artifact-free enough for an unzoomed preview and 100% no severe face/text/mask-seam corruption. Evaluate at 1:1 zoom too; source geometry, text and seams each receive a separate pass/fail field. No single aggregate score conceals fidelity regressions. |
| **Runtime / stability** | All 52 controls/trials complete or accurately report supported refusal/cancel; **zero crashes, ANRs, process kills, OOMs, memory leaks or network requests** in local/airplane mode. Model load failures must leave gallery/scanner usable; no new unapproved dependencies or permission. |
| **RAM / storage** | On **each target phone**, measure Android process PSS/native heap, system available memory and low-memory flag before/peak/after, GPU/driver allocation when exposed, mmap/file cache and install/download bytes. Peak must leave **≥1 GiB system-available headroom** without low-memory, process kill or degrading foreground gallery use. If not measurable, do not pass this gate. Package/download size must be explicitly displayed; no hidden multi-GB install. |
| **Cold start / responsiveness** | On each supported phone, from first explicit Generate to first progress indicator **≤1 s**, model cold-load **p95 ≤15 s**, end-to-end **p95 ≤90 s** at the declared test size across repeated cold/warm runs; cancel acknowledgement **≤2 s** and clean temp files. These are **proposed product SLOs**, not predicted run times. Timeouts are included as failures. |
| **Thermal / sustained speed** | After stabilized room-temperature baseline, repeat **5 consecutive edits** and record Android thermal status [B1], per-edit time and any backend migration. **Never enter THERMAL_STATUS_SEVERE or worse**; final-three median runtime no more than **1.5×** first-two median. Record ambient/surface temperatures if available; never pretend Android thermal status is a precise °C measurement. |
| **Battery / energy** | Airplane mode, fixed brightness, unplugged if safe; record charge counter or energy-counter telemetry [B2] before/after a repeated test block and matched idle baseline. Proposed budget: **≤1% battery capacity equivalent per 512×512 edit** averaged over a block; report uncertainty and whether property is unsupported, and do not infer power from an emulator. Missing reliable energy accounting means **U / NO-GO**, not zero cost. |
| **Waiting / trust** | A truthful local-only badge/label, stated download size, progress phase or explicit indeterminate waiting, working Back/Cancel, no automatic retry or remote upload, copy-on-accept and source unchanged. User can decline model download and keep remote or Erase routes. Observe 5 scripted cancellations and 5 low-space/thermal/error cases without hanging or silent resubmission. |

**Measurement procedure:** warm the phone only through ordinary use; first gather five cold model loads (restart process, confirm model not cached as specified) and at least 20 warm generations per phone at 512×512 (and a separate declared larger-resolution tier if offered). Use monotonic time around load, preprocessing, each inference stage and file save; report p50/p95 and individual timeouts rather than just best case. Collect Android [ActivityManager.MemoryInfo](https://developer.android.com/reference/android/app/ActivityManager.MemoryInfo), process PSS and available native/GPU metrics [B3], [PowerManager thermal status](https://developer.android.com/reference/android/os/PowerManager) [B1], and [BatteryManager](https://developer.android.com/reference/android/os/BatteryManager) [B2], with baseline/methodology [B4]. Capture logs/trace identifiers but **no images, prompts, GPS/EXIF, face vectors or device secrets**. Android Macrobenchmark is useful for scripted timing but its emulator output is **not** a thermal/energy phone benchmark [B4]. Report observed wall-clock waiting and per-device variance; do not combine phones into a misleading universal average.

## Admission rubric / stop rules

- **L0 — legal/provenance:** license and rights (weights **and** ancillary files/tools) verified, version pinned, safe local use and redistribution documented. Failure: **stop**, no packaging.
- **L1 — honest mobile execution:** end-to-end editable-image pipeline can be converted/exported and run locally with all operator fallbacks shown on a representative Android device. Input/mask/reference semantics match claims, offline network test is clean, memory fits before quality testing. Failure: **postpone**.
- **L2 — quantization and accuracy:** compare fp16/bf16 reference with each quantized model on the **same 48 frozen edit cases**; publish fidelity/adherence deltas, off-mask drift and severe-error list, not just model size. A low-bit conversion is inadmissible if it breaks identity or instruction accuracy, even if it runs fast. Failure: **reject quantization or model**.
- **L3 — all hard product gates:** quality, identity, preserved regions, cold start, p95 waiting, energy, peak RAM/storage, thermal and cancellation gates in the table **all pass on every claimed supported device**. No averaging away a failure. Missing metric is **U**, not PASS. Separate independent Review must verify raw evidence and citations.
- **L4 — release decision:** if L0–L3 pass, file a **new**, narrowly scoped code spike with an explicit model + runtime + chipset target, separate human license/asset gate as needed, test/rollback plan and Review. Otherwise retain **NO-GO for general on-device instruction editing**. Local Erase remains a distinct implementation.

**Potential stop-before-phone signals (I):** a reference full-precision workflow requiring around 13 GB desktop VRAM is unlikely to fit the existing Exynos S24+ without substantial operator-specific optimization; a 20B-parameter editing pipeline is not a sensible first mobile target. These are **inferences**, not phone measurements or proof that optimized models can never run locally.
