# fal.ai queue (#429), 2026-11-18

`featureaiedit/provider/hosted/fal/FalImageEditProvider.kt` with `TransportFalExchange` on the shared transport. Fake-server tested only: no key, account or live request was used.

- **Queue contract** (checked 2026-11-18): submit `POST https://queue.fal.run/{endpoint}` with the model input JSON and `Authorization: Key <key>`; reply `request_id`. Status `GET https://queue.fal.run/{owner}/{alias}/requests/{id}/status` → `IN_QUEUE` (with `queue_position`), `IN_PROGRESS`, `COMPLETED`. Result `GET …/requests/{id}` → `images[{url,content_type,width,height}]`, `has_nsfw_concepts[]`, `seed`. Cancel `PUT …/requests/{id}/cancel`. Status, result and cancel use only `{owner}/{alias}`, so `fal-ai/flux-pro/kontext` polls under `fal-ai/flux-pro`.
- **Sources:** `docs.fal.ai` was not reachable from the build session; the contract comes from fal's official JavaScript client `@fal-ai/client` 1.11.0 on npm (`src/queue.js` submit/status/result/cancel and PUT; `src/request.js` `Authorization: Key`; `src/utils.js` `parseEndpointId`; `src/types/common.d.ts` queue statuses; `src/types/endpoints.d.ts` per-model input/output schemas; `src/backup-domain.js` and type docs for the `v3b.fal.media` media host). fal's model API pages state that a base64 data URI is accepted wherever a file URL is.
- **Catalog:** default `fal-ai/qwen-image-edit-2511` (Qwen-Image-Edit-2511, Apache-2.0 weights: up to 4 input images, explicit `image_size`, png/jpeg/webp, seed, up to 4 outputs); `fal-ai/flux-pro/kontext` and `fal-ai/flux-pro/kontext/max` (FLUX.1 Kontext: one image, `aspect_ratio` presets, jpeg/png, seed, `safety_tolerance` 1 to 6 exposed as a typed option). No model is described as unfiltered: fal's safety checker and the model host's moderation still apply.
- **Privacy:** images go up inline as data URIs (no upload to fal storage); results are fetched only from `fal.media` hosts over HTTPS, with no key, no query string, bounded by the transport's 32 MB file cap, and verified by their bytes before they are kept. Result hosts, retention and the pre-live checklist are in "Result hosts and retention (#464)" below.

## Result hosts and retention (#464), 2026-11-19

fal's queue guide says result media URLs are publicly accessible to anyone holding them and expire later; its media-expiration page describes dashboard, request-history and CDN storage. `fal.ai` was not reachable from the build session, so the facts below come from the official client `@fal-ai/client` 1.11.0 on npm (`src/storage.js`, `src/queue.js`, `src/types/endpoints.d.ts`) plus the issue's reading of the docs. No key, paid request or personal media was used.

**Allowed result hosts (all three pinned models).** One rule, `FalImageEditProvider.isFalMediaHost`: `fal.media` or any `<label>.fal.media` subdomain (for example `v3b.fal.media`, the host in the official client's type docs), over HTTPS on port 443, with no user info, query or fragment. Neither the client's schemas for `fal-ai/qwen-image-edit-2511` and `fal-ai/flux-pro/kontext[/max]` nor anything else reachable names a per-model host, so the exact host each model returns is **not verified yet**: record it from the first owner-approved live call (#457) before widening anything.

| Result URL host | Handling |
|---|---|
| `fal.media`, `*.fal.media` | Downloaded without the key, bounded, verified by bytes |
| `storage.googleapis.com/falserverless/…` (used in fal's API examples for other models), `*.storage.googleapis.com`, `fal.ai`, `fal.run`, any other host | `Failed(UNKNOWN, "RESULT_HOST_REJECTED")`: nothing is fetched, nothing is stored, and the source photo is never re-sent anywhere |
| `http:`, `data:`, user info, port other than 443, query string | Same rejection |

Widening the allowlist is a code change with its own test and Review, never a run-time setting or a silent fallback. The submit was already billed when a result is rejected; the user sees an ordinary failed edit.

**Retention sent on every submit.** `X-Fal-Object-Lifecycle-Preference: {"expiration_duration_seconds":3600}`: the header and JSON shape the official client sends on queue submit for `storageSettings.expiresIn` (its `"1h"` preset; it also offers `"immediate"` = 60 s, `"1d"`, `"7d"`, `"30d"`, `"1y"`, `"never"` or a number of seconds). ATLAS downloads results seconds after `COMPLETED`, so one hour only bounds how long a leaked result URL stays retrievable. It governs generated objects, not the request payload in fal's request history. The header goes through `EditHttpRequest.headers`, which refuses credential, cookie, host and transport-owned names and control characters before connecting.

**Not used yet: `sync_mode`.** Both schemas offer `sync_mode` (Qwen 2511: "the media will be returned as a data URI. Output is not stored when this is True"; Kontext: "the output data won't be available in the request history"). It would avoid the public CDN URL entirely, but the result then arrives as base64 inside the queue result JSON, a shape the adapter has not seen on the wire; it needs the live check below before it replaces URL downloads.

**Before the first real personal edit (owner, in the fal dashboard).** 1) Check the account's data-retention / request-history settings and pick the shortest available; 2) confirm, on one synthetic image, the result host and that the URL stops resolving after the requested expiry; 3) decide whether to switch to `sync_mode`. Until then use synthetic images only.
- **Outcomes:** `has_nsfw_concepts=true` (fal returns a black frame) → `Refused("fal:has_nsfw_concepts")` and nothing is downloaded; submit 401/403 → `AUTH`, 429 → `QUOTA`, 5xx → retryable; a failed model run (an HTTP error on the result call) → `Failed(INVALID_REQUEST, "RESULT_REJECTED")`, because the transport hides reply bodies a content-policy rejection there cannot yet be told apart from a bad input. Cancel and the 10-minute queue deadline call the documented cancel endpoint. The submit POST is never replayed; a cancel that lands while the submit is still in flight cannot cancel remotely, because the request id is not known yet.
- **Cost:** no fal price was verified for these endpoints, so `estimateCost` is `null`.
