# fal.ai queue (#429), 2026-11-18

`featureaiedit/provider/hosted/fal/FalImageEditProvider.kt` with `TransportFalExchange` on the shared transport. Fake-server tested only: no key, account or live request was used.

- **Queue contract** (checked 2026-11-18): submit `POST https://queue.fal.run/{endpoint}` with the model input JSON and `Authorization: Key <key>`; reply `request_id`. Status `GET https://queue.fal.run/{owner}/{alias}/requests/{id}/status` → `IN_QUEUE` (with `queue_position`), `IN_PROGRESS`, `COMPLETED`. Result `GET …/requests/{id}` → `images[{url,content_type,width,height}]`, `has_nsfw_concepts[]`, `seed`. Cancel `PUT …/requests/{id}/cancel`. Status, result and cancel use only `{owner}/{alias}`, so `fal-ai/flux-pro/kontext` polls under `fal-ai/flux-pro`.
- **Sources:** `docs.fal.ai` was not reachable from the build session; the contract comes from fal's official JavaScript client `@fal-ai/client` 1.11.0 on npm (`src/queue.js` submit/status/result/cancel and PUT; `src/request.js` `Authorization: Key`; `src/utils.js` `parseEndpointId`; `src/types/common.d.ts` queue statuses; `src/types/endpoints.d.ts` per-model input/output schemas; `src/backup-domain.js` and type docs for the `v3b.fal.media` media host). fal's model API pages state that a base64 data URI is accepted wherever a file URL is.
- **Catalog:** default `fal-ai/qwen-image-edit-2511` (Qwen-Image-Edit-2511, Apache-2.0 weights: up to 4 input images, explicit `image_size`, png/jpeg/webp, seed, up to 4 outputs); `fal-ai/flux-pro/kontext` and `fal-ai/flux-pro/kontext/max` (FLUX.1 Kontext: one image, `aspect_ratio` presets, jpeg/png, seed, `safety_tolerance` 1 to 6 exposed as a typed option). No model is described as unfiltered: fal's safety checker and the model host's moderation still apply.
- **Privacy:** images go up inline as data URIs (no upload to fal storage); results are fetched only from `fal.media` hosts over HTTPS, with no key, no query string, bounded by the transport's 32 MB file cap, and verified by their bytes before they are kept. Inputs and outputs may still persist on fal's side per its terms (`sync_mode` would avoid stored outputs but returns base64 inside JSON; not used yet).
- **Outcomes:** `has_nsfw_concepts=true` (fal returns a black frame) → `Refused("fal:has_nsfw_concepts")` and nothing is downloaded; submit 401/403 → `AUTH`, 429 → `QUOTA`, 5xx → retryable; a failed model run (an HTTP error on the result call) → `Failed(INVALID_REQUEST, "RESULT_REJECTED")`, because the transport hides reply bodies a content-policy rejection there cannot yet be told apart from a bad input. Cancel and the 10-minute queue deadline call the documented cancel endpoint. The submit POST is never replayed; a cancel that lands while the submit is still in flight cannot cancel remotely, because the request id is not known yet.
- **Cost:** no fal price was verified for these endpoints, so `estimateCost` is `null`.
