## Evaluation contract

For each applicable checklist cell score **0** = verified mismatch/failure against its binding anchor, **1** = partly meets it or inconsistent, **2** = meets it and relevant interaction verified in **both** system themes. **?** = not inspected, missing/inadequate evidence or no credible reference; **—** = not applicable with reason. Never turn **?** into zero or two. A verified failure in either theme can establish 0/1; record the failing theme and any uninspected counterpart. Do not award 2 from a single theme or a single static frame for a dynamic action. A row is signed off only when all applicable cells are 2 and actual light/dark captured PNGs and relevant task outcomes have been inspected at the exact head. For every scored 0/1 cell record the concrete observation, component, evidence link, binding reference/finding ID, and desired delta. Score appearance and structure against v3, not Samsung screenshots; score feature availability and in-feature behavior against the parity spec (cite research finding IDs where applicable).

The S24+ evidence target is **1080 × 2340 px at density 450** via `S24DisplayRule`. Synthetic MediaStore images only, never personal photos, faces or embeddings. Existing `saveUiEvidence` instrumentation, `scripts/ci_ui_evidence.sh verify`, `scripts/verify_parity_matrix.py` and [parity matrix](../../scripts/parity-matrix.tsv) provide a capture mechanism; a declared screenshot, filename, manifest entry, passing build, or code audit is not pixel inspection. Review downloads the aggregate emulator artifact from the **PR head**, checks PNG bytes/SHA-256 and per-head manifest, and inspects the actual light/dark pairs for the action **state**, not just its parent screen. `NOT_CAPTURED` means evidence absent; skipped jobs are not proof.

**Evidence provenance:** separate (a) reference research/benchmarks, (b) synthetic annotated pre-build target diagrams, (c) code observations, and (d) actual exact-head Android runtime captures and task observations. (a–c) can guide a brief or evidence backlog but cannot establish a runtime visual score. BRAND pre-build packs (#753, #806/#807/#809) and the pinned code audit [LAPIS_COVERAGE](../design/LAPIS_COVERAGE.md) do not establish runtime scores. Before/after UI evidence must identify both heads, fixture, tester, timestamp, viewport/theme and capture manifest; a new head needs current-head proof. No new runtime renders are claimed in this documentation revision.

## Flow-first ranking for the daily Strategy turn

Per [owner flow-priority update](https://github.com/LPStruiksma/atlas-gallery/issues/120#issuecomment-6900670605), evaluate the task before styling. For each action, inspect whether the primary content stays visible while acting; count taps and scrolls from the approved home through the outcome; check discovery, conventional patterns versus needless invention, plain copy, 48 dp targets, focus/keyboard and accessibility. Cite actual observations (task start/end, taps/scrolls, state, theme and exact-head evidence), not hypothetical counts. Compare against parity behavior, v3 and, for redesign briefs, the Samsung research and at least one benchmark app. A new structure is not a defect just because Samsung places an action elsewhere.

Use the existing frequency × verified failed-cell metric, now split into two **disjoint** counts: classify each verified 0/1 cell as **flow** if a task/accessibility/behavior obstacle is evidenced, otherwise **visual-only** if only appearance differs. If both apply to one cell, classify it as flow and record both observations. If classification lacks evidence, leave it unresolved rather than guessing. Rank verified flow rows before visual-only rows, regardless of frequency. Within the flow tier sort descending by F × flow-failed cells, then F × visual-only failed cells; within visual-only sort descending by F × visual-only failed cells. Tie-break by higher F then inventory order. The combined F × all verified failed cells remains a descriptive lower bound, not the primary rank. Unknowns remain a separate capture-first backlog, never rank them as healthy; incomplete rows' known gap counts are lower bounds, not a complete ordering of all defects.

**F** (1–5, 5 = many times per session) is the prior Strategy estimate from #120, not measured usage. Keep it estimated until an owner-private aggregate is available; only permitted non-sensitive aggregate estimates/provenance may be recorded. Never put raw usage logs or private media in GitHub. Capture priority may use estimated frequency × missing-evidence leverage, explicitly separate from measured gap ranking.

## How to finish a row and rank candidate units

1. Run the existing **API 35 emulator** screenshot pipeline at the PR's exact head with synthetic fixtures. Preserve `ui-evidence/parity-matrix/manifest.tsv`, `coverage.txt`, original PNGs and job URL. Inspect 1080×2340 PNGs in both themes. Add action-state screenshot tests and a `scripts/ui-evidence.d/<unit>.txt` manifest only where needed; do not declare shots no test writes.
2. Compare actual frames to Quiet Frame v3, task outcomes to the parity spec and cited research IDs; check flow before visual-only deltas. For M inspect video/frame sequences plus durations and reduced-motion outcomes; for H inspect hit rectangles, semantics and gestures. A still alone cannot verify either. For D20 test date created, date modified, file name, size and random (plus appropriate extras and direction); D21 test scoped search on every overview, including People, with results/empty/back outcomes. See #175 and existing SORT/FIND units.
3. Replace corresponding ? cells with supported 0/1/2/—; record `Gap: Dn / action-state / cell / flow or visual-only / observed discrepancy / binding anchor and desired outcome / evidence links and theme / test head`. Include tester, fixture, timestamp and manifest. Count verified failed cells once, keep unknown count and apply the flow-first tiered ranking above.
4. Daily Strategy first routes verified flow obstacles to existing owners, then visual-only gaps, using the evidence backlog to resolve unknowns in parallel where ownership permits. Capture missing primary-task states first (Pictures/atlas, viewer/return, navigation, selection, search/sort, then lower-frequency and cross-cutting actions); this is a provisional capture order, not a measured gap rank. Keep capture work with existing BRAND/flow/SORT/FIND units; no replacement V01–V17 queue. Reconcile the current Plan and exact-head CI/renders before marking any row done.

**Important:** this documentation-only change updates the evaluator, not app behavior. No runtime pixel inspection or measured visual scores were performed; the standing daily ranking remains incomplete until real action-state evidence is inspected.
