## Method and limits

This is a **versioned feature/entry-point inventory**, not a Samsung screen-geometry comparison and not a claim of rendered or S24+ parity. I inspected the spec, its removal list/checklist, the owner decision, Quiet Frame, main-source and available test paths, then checked open issue/PR ownership. Each row below states an independently inspectable outcome, its *approved target home* (not necessarily the present navigation), source or test that can be opened at the pinned commit, evidence status, existing owner, and the exact remaining behavior or proof. Referenced test files exist; their presence **does not prove they passed at this SHA**. No Gradle, Node, emulator, device or test execution occurred in this ChatGPT seat. Revalidate statuses when current main changes or the owning PR merges.

**Status semantics:** `present` = concrete source entry/behavior exists (not device-accepted); `partial` = a user-facing element or interaction exists but the defined outcome/home/proof remains incomplete; `missing` = required user entry or behavior is absent in this audited main even if lower-level code exists; `unverified` = evidence cannot establish the behavior either way. A feature with no discoverable entry is not `present` merely because a backend exists. Statuses are **not CI results**.

**Coverage:** 61 independently checkable rows — **24 present**, **26 partial**, **8 missing**, **3 unverified** (unchanged classification from the original audit). 56 rows have a new implementation, evidence or ownership note; the remaining 5 retain baseline source/status and any checked owner state. No status is promoted on the strength of a closed issue, preflight board, backend-only merge or historical runtime result. Sections 0–7 plus binding removals and explicitly authorized ATLAS extras are represented. The private research archive's broader 187 findings is **not public here**; this report cannot certify unseen Samsung features. Where the spec references external finding IDs, rows preserve the section and behavior; conduct a separate research-by-ID check if the full archive is later made available to an authorized seat.

**Evidence levels at the refresh pin (apply to every row):** source status is the matrix status; exact-pin runtime/emulator journey or render = **unknown** for all 61; physical S24+ acceptance = **unknown** for all 61. This is not a claim that CI failed or that no test exists. Historical source-head exception to *unknown historical runtime*: FLOW-1 [PR #1034](https://github.com/LPStruiksma/atlas-gallery/pull/1034) records 30 actually inspected synthetic PNGs and anchor/handover XML/logs from [run 45194391159, attempt 2](https://github.com/LPStruiksma/atlas-gallery/actions/runs/45194391159), source head `cde4f91d197cedcaacc5a225665ff175f65963a7` (GitHub run metadata checked: completed/success, matching head and attempt). Relevant to 0/F7, 2/G3, 2/G4 only; the artifact was not independently inspected in this seat and prior fling anomaly remains unresolved. Other PR descriptions cite authored tests, probes or pre-build render evidence; absent independently verified exact-head run metadata, runtime status stays unknown. No phone/device or UI claim is made by this docs PR. No new owner-approved feature exception was located: the explicit [owner contract](https://github.com/LPStruiksma/atlas-gallery/blob/473610a7ce2bb7fa14019242ab24fc7c180ff6ba/docs/OWNER_INTENT.md) authorizes ATLAS layout and extras, including file-size sort, not omission of Samsung behavior. The spec's [merged tap-ease contract](https://github.com/LPStruiksma/atlas-gallery/blob/473610a7ce2bb7fa14019242ab24fc7c180ff6ba/docs/product/SAMSUNG_PARITY_SPEC.md) identifies 260ms as ATLAS-chosen, not a Samsung measurement; it is not acceptance of unrelated fling gaps.
