## Method and limits

This is a **current-main feature/entry-point inventory**, not a Samsung screen-geometry comparison and not a claim of rendered or S24+ parity. I inspected the spec, its removal list/checklist, the owner decision, Quiet Frame, main-source and available test paths, then checked open issue/PR ownership. Each row below states an independently inspectable outcome, its *approved target home* (not necessarily the present navigation), source or test that can be opened at the pinned commit, evidence status, existing owner, and the exact remaining behavior or proof. Referenced test files exist; their presence **does not prove they passed at this SHA**. No Gradle, Node, emulator, device or test execution occurred in this ChatGPT seat. Revalidate statuses when current main changes or the owning PR merges.

**Status semantics:** `present` = concrete source entry/behavior exists (not device-accepted); `partial` = a user-facing element or interaction exists but the defined outcome/home/proof remains incomplete; `missing` = required user entry or behavior is absent in this audited main even if lower-level code exists; `unverified` = evidence cannot establish the behavior either way. A feature with no discoverable entry is not `present` merely because a backend exists. Statuses are **not CI results**.

**Coverage:** 61 independently checkable rows — **24 present**, **26 partial**, **8 missing**, **3 unverified**. Sections 0–7 plus binding removals and explicitly authorized ATLAS extras are represented. The private research archive's broader 187 findings is **not public here**; this report cannot certify unseen Samsung features. Where the spec references external finding IDs, rows preserve the section and behavior; conduct a separate research-by-ID check if the full archive is later made available to an authorized seat.
