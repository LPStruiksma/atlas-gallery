# Editor-hosted AI tools: working-image, candidate and patch contract (EDIT-5a)

**Status:** normative *semantic* contract for [#642](https://github.com/LPStruiksma/atlas-gallery/issues/642), before the Android adapters in [EDIT-5 #635](https://github.com/LPStruiksma/atlas-gallery/issues/635). This document changes no Kotlin API, provider, media-writing path or UI. **Binding to EDIT-1's final raster-patch API: TBD until [#631](https://github.com/LPStruiksma/atlas-gallery/issues/631) is merged.** Likewise, export, history persistence and Save are implemented by their respective units, not by this document. The traces below describe required behavior, **not tested Android behavior**.

Owner intent: AI Edit, Swap person and LaMa Erase become tools inside **one** editor, with one history and one Save path. Follow [EDITOR PARITY](PARITY.md), the forward [ENGINE contract](ENGINE.md), [AI Edit architecture](../ai-edit/ARCHITECTURE.md), [existing AI Save policy](../ai-edit/SAVE_POLICY.md), [Identity Engine](../identity-studio/ENGINE_CONTRACT.md), [Identity Studio UX](../identity-studio/UX.md) and [on-device Erase](../ai-edit/ON_DEVICE_ERASE.md). These existing standalone subsystems retain their behavior until #635 migrates the entry points.

## 1. Authority, input and ownership

An editor host, not a nested tool, owns the media source, recipe/history, rendering, durable patch store, pending operation, and eventual EDIT-3 Save. A tool has access only to a **bounded, explicitly created working-image snapshot** and to the ancillary inputs permitted for that tool. It returns an ephemeral candidate, never a MediaStore write or a mutation of the recipe.

**The input is the rendered current working image, not the original.** Render the entire recipe *as it is displayed*, including earlier raster patches, geometry/crop, colour, LUT and decorations, at an explicit export/processing resolution. Do not silently use the source file, the image selected when the viewer was first opened, the underlying uncropped bitmap, an implicit gallery album, or a separately selected recent item. Inside the nested tool, "Before", "Original" and comparison mean **this pre-tool working snapshot**. The outer editor's Compare still means the **untouched media original**.

The host creates an operation snapshot with these semantic fields (names here are contract concepts, **not Kotlin declarations**):

| Required identity/input | Invariant |
|---|---|
| Contract version, editor-session ID, operation ID, tool kind | Explicit nonempty, unique within their scopes; operation IDs are never reused after cancel/restore. Reject unknown contract versions. |
| Source revision/fingerprint, recipe schema version and exact recipe/history revision | Immutable snapshot binding. Includes any patch dependencies, geometry state and render specification. A candidate is accepted only against *that* version, not the current selected gallery item. |
| Working raster identifier, full-resolution target width/height, actual supplied width/height, content checksum | All dimensions positive and within the selected tool's validated limits; source identity is not a path or URI sent to a provider. Hashes are of specified canonical bytes, not a display thumbnail. |
| Orientation, pixel origin and axes, colour space/transfer and bit depth, alpha mode, HDR/gainmap policy | The supplied raster is top-left origin, x right/y down, orientation **baked into pixels** (orientation tag = normal). Declare actual ICC/transfer (e.g. sRGB SDR), straight vs premultiplied alpha, and whether gainmap is retained, transformed or unavailable. Never silently flatten HDR/alpha or claim a colour match across undeclared profiles. |
| Working-to-source mapping and mask/region coordinate specification | Versioned coordinate transformation and crop/warp, including resize. If inverse mapping is not valid/unique on the required domain, use a supported full-frame output-space patch or refuse commit. |
| Processing resolution policy | Full export-quality render is preferred; if a provider/device imposes a cap, record actual pixels, scaling, aspect and any loss. Display preview resolution is **not** automatically patch resolution. |
| Operation-owned workspace and lifecycle token | App-private bounded storage, access checked on every restore/accept. The host may delete only the workspace/assets it owns. |

Only a user action can enter a tool. Opening an AI tab or inspecting a photo must not submit, upload, debit credits, or enumerate unrelated media. Before every Generate, capability checks reject unsupported input size/mask/refinement/resolution; the UI discloses provider, destination, estimated charge (if known), and what was selected, without treating an estimate as a guaranteed cost.

### Source, working image and candidate are different things

| Surface | Meaning | Who may change it? |
|---|---|---|
| **Media original** | Bytes/URI originally opened in the editor; retained for eventual byte-for-byte Revert policy. | Only explicit EDIT-3 Save/Revert, subject to MediaStore consent and its backup/journal protections. |
| **Working snapshot** | Frozen rendered image at one exact recipe revision (e.g. crop + adjustments already visible). | No one while the nested tool is working; subsequent editor changes produce a **new** revision. |
| **Tool candidate** | One provisional output, in the operation's private workspace; never the editor's source or a gallery item. | The tool may generate or discard it; the host validates before accepting. |
| **Accepted patch** | Content-hash-backed immutable raster asset referenced by **one** recipe/history operation. | The editor host alone, upon explicit **Use edit** and successful validation. |
| **Saved media** | EDIT-3 export of the whole current editor recipe. | EDIT-3 only, on explicit editor **Save** or **Save as copy**. |

## 2. Pixel spaces, geometry and masks

All geometry is **measured in pixels**, not screen dp, EXIF-coordinate guesses or raw touch coordinates. For working raster W × H, valid integer pixel indices are x = 0..W-1 and y = 0..H-1, with centres (x+0.5, y+0.5). Rectangles use half-open edges [left,right) × [top,bottom), 0 ≤ left < right ≤ W and 0 ≤ top < bottom ≤ H. An optional polygon/face/brush target is described in the **same top-left, orientation-normalised working grid** and clipped to its declared bounds; each mask sample corresponds to exactly one working pixel unless its separately declared mask resolution and transform say otherwise.

**Screen touch → image:** remove pan/zoom/letterboxing and viewport insets, then map through the *current displayed working raster's* inverse presentation transform. Never treat a screen pixel as a source pixel. Reject touches beyond the visible image. Reprojection to EDIT-1 source space uses the snapshotted source→output mapping (including perspective, straighten, rotate/flip, crop, scaling) and its inverse only where valid; retain a transform version and rounding convention. For an inverse-mapped rectangle under a projective transform, use its corners/polygon or rasterised mask, **not an axis-aligned source bounding box that edits pixels outside the selection**. For a crop, the excluded source area stays excluded; a result never resurrects it.

**Mask rule:** an explicit selection is the only masked input. Define mask as single-channel [0,255], with 0 = preserve, 255 = fully targeted; intermediate values are coverage. Re-sample coverage with a documented filter and aligned pixel centres (nearest for binary selection, area/linear for feathered coverage as appropriate). Record the raster/grid and any transform in the snapshot; do not infer a mask from album People recognition or from the provider's response. Region bounding boxes alone are not proof that pixels outside the region are unchanged. For identity targets, translate working-grid face box/landmarks into the existing identity request with this same mapping; references and identities remain local.

**Example (synthetic coordinate trace):** a 4000×3000 pixel source is cropped to source rectangle (left=500, top=350, right=3500, bottom=2350), without rotation, yielding a 3000×2000 working raster at 1:1. A working-space erase selection (left=400, top=250, right=900, bottom=700) maps to source (left=900, top=600, right=1400, bottom=1050). If processing is capped to 1500×1000, map all four edges/mask samples using scale 0.5 with pixel-centre alignment; do **not** send the original-resolution bounds against the reduced raster unchanged. Any subsequent rotate, perspective, adjust or recipe revision invalidates the result's applicability unless the adapter explicitly demonstrates the same rendered snapshot, not merely an unchanged original URI.

**Resolution:** do not upscale a 1024-pixel provider candidate and label it a native-resolution 4000-pixel edit. A lower-resolution result is allowable only if the user-selected output policy and tool capability permit it, dimensions/aspect/crop mapping are explicit, and the UI does not promise full resolution. Unexpected aspect/colour/alpha changes are invalid, not silently stretched or stripped. Full-frame output must match the declared working canvas after the chosen resampling policy. Partial output must name the exact destination rectangle and mask; if an adapter/renderer cannot preserve outside pixels with its chosen compositing path, use an **explicitly supported** full-frame fallback or mark that partial edit unsupported.

## 3. Tool-specific processing boundaries

The host supplies a shared **submit → working/progress → preview candidate → Use edit or Discard** envelope, without replacing any tool's real engine or consent controls:

| Tool | Processing/data boundary | Specific behavior retained |
|---|---|---|
| **AI Edit** | Hosted/self-hosted when explicitly selected; **only after Generate** may the provider receive the rendered working-image copy, the user's prompt and individually selected masks/regions needed for that request. The editor-hosted contract does **not** add People, album, face geometry, identity references, embeddings, source URI, GPS/EXIF, local lineage, search data or hidden snapshots to a remote payload. Sanitise outbound metadata; no implicit service switch/fallback. | Provider selection, first-use disclosure, supported capabilities, cost estimate, journal, explicit unknown outcome, cancellation and resume semantics from [#431](https://github.com/LPStruiksma/atlas-gallery/issues/431) and AI architecture. Candidate preview alone does not save a copy. |
| **Swap person** | Uses existing **on-device Identity Studio** pipeline, locally selected identity profile/references and target face/head; **no remote People/identity upload** or change of route from LOCAL to a paid/self-hosted engine by the editor wrapper. | Existing person/face picker, multiple versions, Compare all, split, refine, consent/route checks, model availability, local candidate handling and process-death restore from [#477](https://github.com/LPStruiksma/atlas-gallery/issues/477) and [Identity Engine](../identity-studio/ENGINE_CONTRACT.md). Selection of a version is not acceptance into editor history. |
| **LaMa Erase** | Existing local-only, offline LaMa model and user-drawn mask; **no network or charge**. | Mask-only inpainting, original-quality coordinate handling, bounded local job and outside-mask pixel guarantee **in the local input grid** documented in [ON_DEVICE_ERASE](../ai-edit/ON_DEVICE_ERASE.md). Validate after mapping/compositing; the original on-disk orientation behavior must not leak through the editor interface. |

A failed capability or privacy check stops **before** upload or model load when possible. No editor wrapper may silently weaken the tool's consent/permissions/processing route, or change an Identity Studio "local only" workflow into a remote one. A first-use acknowledgement is not permission to submit again after the image, prompt or provider changes: every billed operation still requires Generate.

## 4. Candidate → one EDIT-1 raster patch

**Generate/compute does not edit history.** A successful tool result is an ephemeral, verifiable candidate in app-private storage. A candidate carries the exact operation/session/revision token; requested/actual dimensions; image colour/alpha/orientation; source/working transform; optional edit region/mask and their grids; checksum; tool kind; and safe provenance. It can be previewed, compared against the pre-tool snapshot and discarded repeatedly. The host must not keep two accepted versions of one operation by accident.

On **Use edit**, the host:

1. Acquires an exclusive commit for that operation, verifies it is not already accepted/cancelled, and compares its bound source/recipe revision and render specification to the **current** editor state (not just same URI). A stale/late result cannot be accepted; offer a fresh deliberate run. A saved undo/redo state or a changed tool mask is a new snapshot.
2. Checks that all raster and mask files are still inside a host-owned private workspace, are ordinary accessible files (no unsafe link escape), decode to bounded dimensions, have the expected orientation, transfer/colour and alpha mode, and match their declared content hashes, region, pixel alignment and content-addressed storage policy.
3. Converts the candidate to the supported compositor patch space without double-applying earlier work. The resulting stored **immutable raster** has a full SHA-256 content hash and optional mask hash; its patch specifies actual native pixel dimensions, destination rectangle, alpha/replacement semantics, and whether it is a full-frame replacement or a proven partial compositing operation. A masked replacement uses out = a × candidate + (1 − a) × before in a declared working/compositing colour space; when the mask is binary, all unselected pixels must be bit-identical at the appropriate stage. Never mistake a provider's approximate inpainting region for a pixel-exact mask guarantee.
4. Atomically persists the candidate patch asset and **exactly one** EDIT-1 history operation; if any validation, persistence, version check or commit fails, history and media remain unchanged, and any orphan asset is safely reclaimed. Concurrent double-taps, resumed worker delivery and repeated callbacks cannot append a second patch. Retain hashes referenced by active undo/redo/restorable states; garbage-collect only unreachable app-owned assets.
5. Returns to the editor with Undo enabled. **Undo** removes the patch from the displayed recipe; **Redo** restores it using the same retained hash; **Compare** displays the original media; **Revert** returns to the untouched original, subject to EDIT-3's Save/Revert distinction. A later native edit is another step in the same history. No nested UI can call Save during this sequence.

### Mandatory stage-order compatibility check (binding TBD)

[EDIT-1 #631](https://github.com/LPStruiksma/atlas-gallery/issues/631) currently proposes **source-space** raster patches before geometry, colour, LUT and overlays. Its draft patch fields are tool, content hash, source-normalised rect, native width/height and optional mask hash. But this contract supplies the **fully rendered post-geometry/post-colour working image** to AI tools. Naively installing that output as a source-space patch would warp, colour-adjust or overlay it **a second time**, and source-to-output inversion alone cannot undo non-invertible filters or opaque overlays. That is **not acceptable**.

EDIT-5 adapters must prove one of these equivalent representations against the *whole* recipe, preview **and** export: (a) an engine-supported **post-render, output-space** immutable patch/compositing stage with stable ordering; or (b) an explicitly specified lossless equivalent composition/rebase that preserves the earlier operations, original/compare, undo/redo and future edits. If neither exists for the current recipe, **disable Use edit with an accurate unsupported-result explanation**, keep the provisional result for discard, and append nothing. A full-frame **output-space** replacement is the preferred fallback where supported; a full-frame **source-space** patch is *not* a universal fallback. No hidden recipe flattening, history deletion, duplicated filters or second save path. The specific EDIT-1 API binding and renderer enforcement remain **TBD for #635**, not asserted as merged or compiler-verified here.

## 5. Provenance, safety and eventual Save

A patch has a **privacy-safe semantic provenance**: schema/version, stable operation ID, tool category (AI Edit / identity face-or-head / Erase), processing class (local vs explicitly chosen external provider), candidate/patch hash, selected working revision fingerprint, dimensions, changed-region/mask hash when applicable, and whether a full-frame fallback was used. It may retain a minimal bounded engine/model identifier **locally** if necessary for diagnostics/lineage. Never include real person names, identities, embeddings, target-face images, full prompts, account identifiers, private paths/URIs, GPS, device secrets or raw input media in exported metadata, logs, CI, GitHub or screenshots. Full operational lineage and optionally prompts belong only in the existing app-private, no-backup local lineage system under its retention policy.

The **saved output** must be marked AI-edited under [AIE-26 #458](https://github.com/LPStruiksma/atlas-gallery/issues/458) and [SAVE_POLICY](../ai-edit/SAVE_POLICY.md): a human-readable "Edited with AI" marker in supported app surfaces, and the adopted XMP/IPTC Digital Source Type **compositeWithTrainedAlgorithmicMedia** for a qualifying saved edit. This label is **not** a claim of C2PA signature or authenticity, and it must not leak the prompt, model key, People data or personal provenance. If output format cannot carry the chosen metadata, EDIT-3 must report/handle that limitation rather than silently claiming preservation; the original remains unlabelled/untouched.

**Only EDIT-3 owns Save, Save as copy and post-save Revert.** The editor applies an AI patch to its recipe first, then an explicit outer Save goes through the same export, EXIF/HEIF/HDR/motion-photo policy, MediaStore consent, pending-row journal, lineage and cache refresh as a native edit ([#633](https://github.com/LPStruiksma/atlas-gallery/issues/633)). In-editor **Use edit is not Save**. While editor-hosted, disable or replace AI Edit's standalone "Save copy" and Identity Studio's standalone "Save" with **Use edit**; neither nested saver may insert or modify media. Their independent standalone entry points and save paths remain functional until #635 deliberately migrates them. The original media is not changed merely by opening the editor, generating candidates, accepting a patch, leaving or reopening. A failed outer Save leaves the dirty recipe recoverable; it never falls back to an inner saver.

## 6. States, errors, cleanup and resume

| State and event | Result and legal next action | Recipe/MediaStore effect |
|---|---|---|
| Open tool → **Ready** | Freeze session/revision; show current working pixels; capabilities, first-use and cost/destination if remote. | None |
| User explicitly **Generate** / create local version → **Submitted/Working** | Record durable job/token before dispatch. Report only measured progress; provider journal owns pending/unknown-billable state. | None |
| A validated result → **Candidate** | Keep a preview in owned private storage; compare to pre-tool working snapshot; choose version/refine, Use edit, Discard. | None |
| **Use edit** with unchanged revision → **Accepting → Applied** | Validation + one atomic content-addressed patch/history commit; return to editor. | One history step, zero media writes |
| **Back/Discard** (with or without candidate) → **Discarded** | Confirm when current tool's candidate UI requires it; request best-effort cancel if already sent; clean owned temp artifacts without deleting an accepted/retained patch. | None |
| Validation failed, bad hash/dimensions/colour/mask, inaccessible path, stale revision → **Invalid/Stale** | Explain, refuse Use edit, and offer Discard or explicitly run again. A late callback cannot revive a cancelled operation. | None |
| Offline / auth / quota / provider refused / no face / no model / timeout proven before submit → **Failed** | Show relevant tool-specific recovery; no automatic provider switch. "Nothing was sent" only when proven. | None |
| Submit might have happened; timeout, crash or lost acknowledgement → **Outcome unknown** | Explain that provider **may have charged**; Check again/restore journal or Discard. **Never auto-retry or resubmit** an uncertain billable request. | None |
| Process death / rotation / background → **Restoring** | Rebind same session ID, revision, journal and valid candidate/owned files; restore Working, Candidate or truthful Unresolved. Never invent a success or repeat a commit. | No duplicate history/media write |
| Outer editor **Save/Save copy/Revert** | EDIT-3 alone writes or restores with its required consent/journal/rollback, then invalidates old pending tool snapshots. | Only EDIT-3 changes MediaStore |

Cleanup is ownership-scoped: temporary uploads, generated candidates, abandoned attempts and orphan files are deleted from their **own** app-private directories, without following symlinks or deleting other sessions' or the media source's files. Preserve candidates required for a valid resume, and patch hashes reachable through Undo/Redo/history. Remote cancel is best effort, not a promise that a provider did not receive content or charge; provider-side deletion/retention is outside ATLAS's guarantee. No personal images, prompts, identities or embeddings enter development evidence.

## 7. Worked synthetic journeys (required future integration tests)

These are **expected** states for disposable synthetic images; numbers and prompts are illustrative. Each trace asserts history count, snapshot binding, render equivalence and no nested MediaStore write.

**Trace A — Crop → AI Edit → Use edit → Undo → Redo → Save.**

1. Open a synthetic 4000×3000 test image, crop to a 3000×2000 working canvas. Recipe has **one** geometry operation. The AI Edit tool receives a frozen, orientation-normalised **3000×2000 rendered raster** with crop transform and current recipe revision; it must not receive the original uncropped 4000×3000 image. If service cap is 1500×1000, declare that exact downscale/candidate-resolution policy.
2. Choose a configured provider, enter synthetic prompt "change the blue wall to green", view destination/estimated cost, then tap **Generate**. Only then may the sanitized working image and text be transmitted (and selected masks only if present). The result is a provisional 3000×2000-equivalent candidate; history remains at **1**, and no MediaStore item exists.
3. Tap **Use edit**. Only if the stage-order compatibility check in §4 passes may the host create one immutable AI-edit patch and atomically append it. History is now **2**. In particular the crop must **not happen twice**, and no second copy is saved. Otherwise the test expects an explicit unsupported result and **zero** new operations.
4. **Undo** displays the cropped pre-AI image with 1 operation; **Redo** restores the same hashed candidate with 2. **Compare** shows the original full uncropped media without altering history. Outer **Save as copy** creates exactly one output with the AI label and preserves the original; outer Save-in-place uses EDIT-3 permission/original-backup rules. Neither nested tool writes a media row.

**Trace B — Adjust → Swap person → Use edit → Revert.**

1. Open a synthetic 1200×800 image of drawn faces, add an exposure adjustment; history **1**. Swap receives **the adjusted working image** and its version; the locally selected synthetic profile/reference images never leave the device.
2. Choose a drawn face in working pixels (for example bounding region (left=260, top=180, right=420, bottom=370)), select one of several locally produced versions and compare against the adjusted *pre-swap* image. Changing a version does not change editor history or invoke Save.
3. Tap **Use edit**. The host accepts only a valid mapped face/head mask and one patch while keeping prior adjustment semantics correct; history **2**, zero MediaStore writes, no identity identifier in portable metadata. If the source-space pre-colour renderer would reapply exposure or misplace the face, reject the commit until equivalent output-space rendering exists.
4. Outer **Revert** displays the pristine synthetic original, no applied editor operations (with reversible history as EDIT-1 defines); only an explicit EDIT-3 Save/Revert action may alter previously saved bytes.

**Trace C — Mask → LaMa Erase → Cancel/timeout (no change).**

1. Open a synthetic 1024×768 image and draw a working-grid mask over (left=200, top=300, right=300, bottom=420); its mask raster, colour/alpha and working revision are pinned. Mask selection is only provisional tool state.
2. Start **local** LaMa Erase. If the user presses Back/Discard while it runs, cancel best effort, clean its owned temporary attempt, invalidate its acceptance token and keep the editor recipe **unchanged**. If a simulated timeout/invalid 512-window result arrives later, it cannot append a patch; no automatic retry, no network call, no charge.
3. Reopen the editor: unchanged pixels and same history. If a separate fresh local erase later succeeds, only an explicit Use edit can accept it; outside-mask preservation is verified at the final compositor stage, not inferred from LaMa's internal model window.
